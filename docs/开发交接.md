# 开发交接

本文件记录 `v0.96.0` 后的接手边界。已验证能力见 [阶段说明](阶段发布-v0.96.md)，候选计划不代表已实现能力。

## 当前状态

- 开发顺序保持 **Maya-first、Blender-second**；Blender 只保留早期合同可行性验证。
- Maya 侧已有 96 个功能纵向切片；当前 main 包含 v0.96.0 后的核心组合、躯干 FK、脊柱 IK/FK 与控制空间扩展，包版本不增加。295 项纯 Python 回归通过，仓库含 85 个宿主 smoke 脚本。
- `BuildBodyCharacterRig(host).apply(include_torso=True, include_spine_ik=True)` 组合独立脊柱机制与全身控制。Spine 模式有 8 个身体 FK 控制、6 个机制关节、IK chest goal、pole 和 waistRoll；原 Torso-only 入口继续保留 7 个 FK 控制。
- `MatchBodySpine(host).execute(rig.plan.torso.torso.spine, "ik" / "fk")` 在当前帧匹配并切换，比较全部 Body 世界矩阵，阈值 `1e-4`，失败整体回滚。固定三关节拓扑，正等比缩放；匹配不写关键帧，不支持动画层或部分混合状态。
- Maya 2024 的 30 / 70 关节完整角色脊柱 smoke 和旧 Torso-only smoke 已通过。证据与完成边界见 [核心开发进度](核心开发进度.md)，三组实现已接通，综合验收见该进度记录。
- `include_control_spaces=True` 要求 Torso，增加头部朝向与左右手脚 IK 共 5 组空间。`SwitchBodyControlSpace(host).execute(rig.plan.control_spaces, "hand_R", "body")` 保持当前世界姿态；手脚 goal 与 pole 成组切换，头部位置仍跟随颈部。30 / 70 关节后台通过，最大矩阵误差约 `7.56e-14`。不写键、不承诺整段动画无跳变。
- `examples/maya_complete_character.py` 提供 30 / 70 关节全身贯通示例，分别生成 348 / 828 顶点代理网格，全部顶点显式写入两关节归一化权重。全身动作、脊柱匹配、空间切换、全局变换与蒙皮方程逐点核对；整个流程支持一次 Undo / Redo 和蒙皮阶段失败整体回滚。
- Maya 事务为本次新建 transform / joint 记录无输入局部变换；通过 UUID 排除既有对象，修复世界空间构建命令在 Redo 时依赖未恢复父级的问题。重做后的身体 / offset / 网格位置与构建结果一致。
- 保持先完成一组连贯实现、再集中验证的节奏；MoCap、Blender、Face、产品 UI 与外围集成继续冻结。

## 实施边界

1. `src/adv_py/core/` 保持 DCC 无关，表达数据、计划与校验；`application/` 编排用例；`adapters/maya/` 执行 Maya 场景操作。不要把 `maya.cmds` 或 `bpy` 引入核心。
2. 写入前检查对象归属、名称、类型、锁定与外部连接；在单一 Maya Undo 事务中提交；提交后从场景读回验证。失败不能留下半成品。测试用自行生成的场景和骨架。
3. 不提交 AdvancedSkeleton 原始 MEL、模板、图标、场景、文档或逐行派生代码。授权安装只作为本机行为参考；仓库保持私有，包元数据当前为 `Proprietary internal tooling`。
4. 不修改、构建、提交或推送 `D:\work\_tools\resume-shen-yuyan-editable`。作品展示如需同步，只处理另行授权的个人主页仓库 `D:\work\_tools\Ubik42.github.io`；普通功能开发不自动改主页。
5. 不启动 Maya 或 Blender 图形界面。先完成一组连贯的核心代码与架构改造，再集中运行相关纯 Python 回归和后台角色 smoke；测试失败再针对修复复验。代码内的场景预检、事务回滚与读回属于运行时合同，继续保留。
