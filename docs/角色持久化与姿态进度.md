## 数据和事务边界

登记数据采用白名单字段和安全 JSON / Maya message 连接，不采用 pickle、eval 或动态类恢复。登记记录操作需要的绑定数据与角色语义，不把整个构建快照作为不透明对象保存。只读解析必须核对版本、结构、节点身份及连接；缺失或受污染的数据不能通过相似名称猜测恢复。

首批支持标准非引用单角色。改名、namespace、多角色和外部结构修改的支持范围由实现与实际验收确定，未验证模式明确拒绝。

全身姿态记录声明过的可编辑控制通道、必要用户属性和空间状态，不记录机制输出。兼容性限定到拓扑、绑定布局与特性一致的角色。静态应用不隐式清除已有动画，不支持动画层、动画区间空间切换或全身带键姿态；旧 Hand Pose 和旧构建接口保持兼容。

姿态恢复必须在一笔事务中按确定顺序处理空间、控制值和复检。占用通道在写入前拒绝；复检失败整体回滚。完整验收同时比较 Body 世界矩阵和实际蒙皮顶点，不能以通道值一致替代最终变形正确。

## 验收方式

使用自生成角色和代理网格，临时 `.ma` 场景、JSON 结果和日志放在忽略的 `validation/results/`。生产进程保存场景后退出，新的 Maya standalone 进程重新载入并发现角色，继续脊柱匹配、空间切换和姿态恢复。30 / 70 关节分别验收，报告记录具体环境与误差。

每批先完成 core、application、adapter 和实际入口，再集中运行相关回归与宿主验证。失败后只复验受影响范围；通过的整批复核、更新记录并推送 main。全部三批完成后结束 goal，不自动扩展到 UI、Blender、Face、MoCap 或外围工具。


## 第一批结果

`RegisterBodyCharacter(host).apply(rig)` 在明确的登记事务中创建 `AdvPy_CharacterRegistry`。登记包含完整控制通道、绑定布局、脊柱和空间操作参数，以及节点 UUID、完整路径、类型、父级和变换输入连接；原生 message 数组将登记连接到实际对象。登记前要求仍处于构建返回的绑定姿态，已经蒙皮不影响登记。标准 30 / 70 关节分别声明 157 / 261 个用户通道。

`ResolveBodyCharacter(host).discover()` 只读列出登记；`execute()` 校验 JSON 摘要、版本、Body provenance、成员连接与身份，并复核脊柱和空间结构。返回的 `spine` 和 `spaces` 可直接用于 `MatchBodySpine` 和 `SwitchBodyControlSpace`。该读取不创建新节点、不改变选择、时间、Undo 顶部或场景修改标志。

295 项 Python 回归通过。`maya_character_registry_smoke.py` 对 30 / 70 关节分别运行独立 write / read 进程：保存重开后恢复上下文并进行脊柱双向匹配和全部空间切换；验证登记失败回滚、登记 Undo / Redo、变换输入断开拒绝、成员改名拒绝、撤销改名恢复，以及损坏登记文档拒绝。姿态矩阵误差按 `1e-4` 阈值验收。

首版不支持登记节点或成员改名、namespace、引用或多个登记角色。登记覆盖完整 Torso / Spine IK / 控制空间组合，旧构建入口不自动增加登记节点。单独登记的 Undo 只移除登记，保留已有角色和蒙皮。全身姿态 capture / apply 和相应文件往返尚未实现，整个 goal 继续进行。
