## 数据和事务边界

登记数据采用白名单字段和安全 JSON / Maya message 连接，不采用 pickle、eval 或动态类恢复。登记记录操作需要的绑定数据与角色语义，不把整个构建快照作为不透明对象保存。只读解析必须核对版本、结构、节点身份及连接；缺失或受污染的数据不能通过相似名称猜测恢复。

首批支持标准非引用单角色。改名、namespace、多角色和外部结构修改的支持范围由实现与实际验收确定，未验证模式明确拒绝。

全身姿态记录声明过的可编辑控制通道、必要用户属性和空间状态，不记录机制输出。兼容性限定到拓扑、绑定布局与特性一致的角色。静态应用不隐式清除已有动画，不支持动画层、动画区间空间切换或全身带键姿态；旧 Hand Pose 和旧构建接口保持兼容。

姿态恢复必须在一笔事务中按确定顺序处理空间、控制值和复检。占用通道在写入前拒绝；复检失败整体回滚。完整验收同时比较 Body 世界矩阵和实际蒙皮顶点，不能以通道值一致替代最终变形正确。

## 验收方式

使用自生成角色和代理网格，临时 `.ma` 场景、JSON 结果和日志放在忽略的 `validation/results/`。生产进程保存场景后退出，新的 Maya standalone 进程重新载入并发现角色，继续脊柱匹配、空间切换和姿态恢复。30 / 70 关节分别验收，报告记录具体环境与误差。

每批先完成 core、application、adapter 和实际入口，再集中运行相关回归与宿主验证。失败后只复验受影响范围；通过的整批复核、更新记录并推送 main。全部三批完成后结束 goal，不自动扩展到 UI、Blender、Face、MoCap 或外围工具。


## 第一批结果

`RegisterBodyCharacter(host).apply(rig)` 在明确的登记事务中创建 `AdvPy_CharacterRegistry`。登记包含完整控制通道、绑定布局、脊柱和空间操作参数，以及节点 UUID、完整路径、类型、父级和变换输入连接；原生 message 数组将登记连接到实际对象。登记前要求仍处于构建返回的绑定姿态，已经蒙皮不影响登记。标准 30 / 70 关节分别声明 157 / 261 个用户通道。

`ResolveBodyCharacter(host).discover()` 只读列出登记；`execute()` 校验 JSON 摘要、版本、Body provenance、成员连接与身份，并复核脊柱和空间结构。返回的 `spine` 和 `spaces` 可直接用于 `MatchBodySpine` 和 `SwitchBodyControlSpace`。该读取不创建新节点、不改变选择、时间、Undo 顶部或场景修改标志。

295 项 Python 回归通过。`maya_character_registry_smoke.py` 对 30 / 70 关节分别运行独立 write / read 进程：保存重开后恢复上下文并进行脊柱双向匹配和全部空间切换；验证登记失败回滚、登记 Undo / Redo、变换输入断开拒绝、成员改名拒绝、撤销改名恢复，以及损坏登记文档拒绝。姿态矩阵误差按 `1e-4` 阈值验收。

首版不支持登记节点或成员改名、namespace、引用或多个登记角色。登记覆盖完整 Torso / Spine IK / 控制空间组合，旧构建入口不自动增加登记节点。单独登记的 Undo 只移除登记，保留已有角色和蒙皮。本批登记接口保持独立，后续姿态与综合结果见下文。

```python
from adv_py.application import RegisterBodyCharacter, ResolveBodyCharacter
from adv_py.application import MatchBodySpine, SwitchBodyControlSpace

registered = RegisterBodyCharacter(host).apply(rig)
# 保存并重新打开场景后，只需新的 host。
character = ResolveBodyCharacter(host).execute()
MatchBodySpine(host).execute(character.spine, "ik")
SwitchBodyControlSpace(host).execute(character.spaces, "hand_R", "body")
```

本机结果为忽略目录 `validation/results/registry30/` 与 `registry70/` 中的 `write.json`、`read.json` 和临时场景。全身姿态以已登记通道和绑定兼容摘要为基础，空间偏移属于恢复合同。


## 全身姿态与最终综合结果

`CaptureBodyCharacterPose.execute()` 捕获登记通道、五组空间状态、九个空间目标矩阵以及 Body 世界矩阵参考。文档使用语义标识，完全不包含 DAG 路径或 UUID，带独立格式版本、内容摘要和绑定兼容摘要。Body 矩阵只用于读回复检，不直接写入受约束骨骼。

`ApplyBodyCharacterPose.plan()` 校验数据完整性、通道范围和角色兼容性，并对静态写入做只读预检。`.apply()` 在单一事务中复核登记与原姿态，先写完整控制值，再按所保存的来源和目标矩阵恢复空间约束偏移，最后逐项读回控制、空间和 Body。空间模式相同也不能跳过偏移恢复，否则中途重绑定后仍可能留下不同的世界姿态。所有比较使用 `1e-4` 阈值，任一失败整体回滚。

`save_character_pose` 在目标同目录写入并复检临时文件，通过原子硬链接发布新文件；已有目标或并发创建目标均拒绝，清理临时文件，不覆盖已有内容。`load_character_pose` 限制文件大小并复用严格解码。标准单位为 cm / degree；当前只支持静态姿态，不清除动画、不自动写键。实际调用见 [已保存角色示例](../examples/README.md)。

299 项纯 Python 回归通过，覆盖版本、未知和重复字段、非有限数值、范围、兼容性、字段完整性、路径无关 JSON、文件往返以及并发写入保护。原 Hand Pose JSON 后台验收作为兼容检查保留。

`maya_character_pose_smoke.py` 每个拓扑使用两个独立 Maya 2024 进程。write 生成并登记角色，捕获带躯干、头部、双侧四肢 FK / IK、足部属性、70 关节手指、混合空间和 1.3 倍 Global 缩放的非中性姿态；随后扰动全部 157 / 261 个登记通道并翻转全部空间，保存已扰动场景。read 只从保存场景和 JSON 恢复，不传递任何 Python 构建对象。

## 完成范围

三组实现均已接通。支持标准完整控制组合、无 namespace、非引用的单角色，兼容性限定到相同拓扑、绑定布局、通道范围和特性。支持保存重开后操作和全身静态姿态往返；不包含改名迁移、多角色、跨骨架重定向、动画区间空间切换、动画层或全身带键姿态。旧构建与旧 Hand Pose 接口保持独立，不会自动登记或转换旧文件。
