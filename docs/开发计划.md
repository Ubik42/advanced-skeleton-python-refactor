## 开发顺序

1. **补齐 Body 相关缺口。** 开发从当前源码与实现差异继续，成批处理 RP、可选控制层、随动、附件、非对称与保存图恢复中的未完成逻辑。左臂近直线输入仍有约 0.00014226 的差异，原定门槛为 0.0001；开发需要保留这个失败事实并修复原因。局部求解诊断遇到阻碍时，开发继续其他相关功能。
2. **补齐 Face 完整流程。** 开发需要覆盖 Fit、构建、控制、变形、身体连接、权重、转换、保留数据重建及撤销重做。Mixed 当前输入的完整来源对照和生命周期已通过。普通 OPM Complete 的完整重建来源与生命周期已通过；多层编辑权重保留仍失败。开发继续整体 Body/Face 组合、其他 Face 构建配置和未完成的保留范围。开发需要区分功能缺口与原版自身限制。
3. **完成其余原版功能与入口。** 开发需要核对 AutoPlace、自定义控制与变形、Game/SDK、动画、旧角色兼容、命名空间以及原版面板排布。开发以有效源码调用为依据补齐遗漏。已有通过范围继续复用；低影响外观与罕见组合排在主体之后。
4. **集中验证完整角色。** 每个相关业务批次完成后，开发集中验证原版姿态、蒙皮变形、动画保留、保存重开、重建、撤销重做及导出。验证使用已有参考与保存场景。验证结果需要区分代码接入、当前运行通过、失败和原版输入限制。
5. **确认 Maya 阶段完成。** 工程需要有有效源码功能与 Python 入口的对应记录。核心功能需要通过真实 Maya 验证。记录需要明确未覆盖范围和继承限制，开发需要处理全部已知业务缺口。用户确认后续方向后，工程再安排 Blender 迁移与性能优化。
