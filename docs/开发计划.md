# 开发计划

更新日期：2026-09-26

## 当前结论

工程尚未完成 AdvancedSkeleton 的全量复刻，也没有足够证据声称原版源码行为已全部重建。

当前成果是一个可运行、可测试的 Maya Python 绑定框架：Fit 数据、基础 Body、四肢与手部控制、可变脊柱、蒙皮、姿态与动画、MoCap、FBX、基础 Face 工作流均已有纵向实现和自生成场景验证。界面已按 AdvancedSkeleton 6.925 的栏目顺序组织，但大部分原版栏目仍没有对应操作；生产资产覆盖、完整 FaceSetup、原版逐项行为对照和 Blender 正式迁移也未完成。

在建立可审计的原版功能清单前，不给出整体完成百分比。现有测试数量只能说明已经实现部分的稳定性，不能代表原版功能覆盖率。

## 完成标准

“全量复刻完成”必须同时满足以下条件：

1. 建立原版功能覆盖矩阵，每个公开操作都有“已实现、明确不实现、待实现”三者之一的结论。
2. 已实现操作覆盖输入、结果、失败条件、撤销／重做、保存重开和场景所有权边界。
3. Maya 可见界面中的入口、参数和反馈能完成对应工作流，不依赖开发命令补齐步骤。
4. 至少使用一套公开示例角色和多套自建差异角色完成 Fit → Body → 控制 → Skin → Animate → Export 全链路。
5. 生产常见的命名空间、引用、动画曲线、多个 Skin、外部驱动和重建场景通过验收。
6. 文档准确区分已实现能力、已验证范围和仍未覆盖的情形。

## 开发顺序

### P0：建立可度量的覆盖基线

- 已建立 [功能覆盖矩阵](功能覆盖矩阵.md)：49 个末级栏目均有唯一编号和当前入口状态；Body / Fit、Edit、Build、Pose、Tools、Publish、Export 已拆到操作、输入、结果、失败边界和证据层。
- 从原版公开界面、帮助文档和合法可用的本机安装行为整理功能矩阵。
- 为每个操作记录输入、场景变化、输出、失败条件及当前实现入口。
- 将“按钮存在”“后台用例存在”“生产工作流通过”分开计数。

完成条件：所有顶层栏目和公开子操作都有唯一编号与状态，可以据此计算真实行为覆盖率。当前完成栏目层及 Body / Fit、Edit、Build、Pose、Tools、Publish、Export 操作层；其他 Body、Face 和工具栏目仍需拆分。

### P1：完成 Maya Body 主链路

- 用公开示例角色完成 Fit、Body、控制构建、蒙皮、姿态、动画和导出。
- 补齐主链路中仍需命令行或手工拼接的步骤。
- 覆盖重建、命名空间、引用、撤销／重做和保存重开。

完成条件：用户只通过 Maya 界面即可从标准 Fit 得到可动画、可导出的完整角色；输出场景可独立重开。

### P2：补齐高频 Body 与 Deform 功能

- 按覆盖矩阵优先实现高频身体编辑、自定义控制器、局部关节和变形选项。
- 为每一组连贯工作流增加对应的宿主验收，不按单个函数反复测试。
- 使用不同关节数、比例、命名空间和两类以上网格验证。

完成条件：高频 Body／Deform 操作全部有界面入口和真实 Maya 结果，失败时不留下半成品。

### P3：完成动画、MoCap 与发布兼容

- 实现带键控制空间切换的历史动画保持。
- 扩大 FBX、帧率、单位、旋转顺序、动画层和外部曲线覆盖。
- 补充自动映射与可保存映射预设。

完成条件：多段现有动画在模式与空间转换后保持可接受误差；外部输入和发布结果可重复验证。

### P4：完成 Face 工作流

- 建立面部标记、求解、控制、变形器和资产版本的完整数据合同。
- 实现眼睑、下颌、表情组合和复杂目标管理。
- 使用公开或自建的不同面部拓扑验证。

完成条件：从面部准备到表情动画可通过界面完成，重建和版本刷新不会破坏已有动画。

### P5：收口界面与生产验收

- 移除主工作流中的“尚未实现”入口，或在覆盖矩阵中明确排除原因。
- 对照原版检查栏目排布、操作入口、参数默认值和状态反馈。
- 录制并保存一套完整可见 Maya 验收证据。

完成条件：覆盖矩阵中计划支持的 Maya 项全部关闭，没有依赖隐藏开发入口的步骤。

### P6：启动 Blender 第二阶段

只迁移已在 Maya 中稳定的数据合同和用例语义。Maya 主线未达到 P5 前，不以 Blender 原型增加整体完成度。

## 开发与验证节奏

每轮先完成一个可操作的纵向工作包，再集中验证：

1. 完成 Core、Application、Maya Adapter 和界面入口。
2. 运行该工作包的纯 Python 回归和一个真实 Maya 场景验收。
3. 在里程碑结束时运行完整回归、架构边界检查和关键宿主场景。
4. 只保留脚本、固定夹具和结论；临时场景、截图、日志与调试探针不进入长期工程。

## Codex Goal

完成 AdvancedSkeleton Python 重构的 Maya 主线。以本计划和功能覆盖矩阵为基线，持续快速循环：每轮选择一个能在 Maya 界面中从输入走到结果的工作包，连续完成 Core、Application、Maya Adapter 和界面入口后集中验证，不按函数反复运行全套测试。每轮至少用一套真实 Maya 场景检查实际绑定动作、失败回滚、单次撤销／重做与保存重开；通过后更新覆盖矩阵和计划，清理可再生成的残留，提交并推送公开仓库。若验收未过，修复同一工作包并重测，不把按钮存在或测试数量计为功能完成。下一工作包将原版网格与 Skin 安全带入由 Fit 文档构建的新角色场景，明确 68 个辅助／分段影响关节的权重和驱动保留方案。Maya 主线验收后再启动 Blender 阶段。

当前循环：扩展 Control Orient。CO-05 的自建角色双侧臂腿 FK、ArmIK、LegIK、ToeIK 和 FK 模式肩胛控制通过三轴后台采样；Pole Vector 旋转没有 Body 驱动，只更新方向。肩胛切到 IK 模式后的 Z 轴约有 5% 动作量的朝向误差：肩、肘位置对称，关节朝向未完全镜像，调整控制器正负号或倍率不能消除。手部和公开示例角色未验，CO-05 保持部分完成。CO-06 World Match 已按本机 6.925 MEL 的变形关节 X 轴主导世界轴规则实现，通过自建角色十二类双侧 FK／IK／Pole Vector 及命名空间五指控制的 Maya 改向、Body 静止、Undo／Redo 与重开；六种正负主轴矩阵与 Maya 约束逐项吻合。Mirrored Behavior 组合和原版 `sam.mb` 数值对照待验。“朝向子关节”另列为 CO-X1 扩展。CO-07 World Orient 已按原版记录 X Primary／Z Secondary，并通过自建角色十二类双侧控制和命名空间五指控制的 Maya 后台基线。

原版 `sam.mb` 已以禁止脚本节点执行的方式在 Maya 2024 打开：场景为 Y Up、厘米单位，含 41 个 Fit 关节、294 个总关节、141 个控制曲线 Transform 和 1 个网格。原版 41 个 Fit 关节可被当前对称规划器展开成 74 个 Body 关节；原场景已有同名 Body，且 30 个 Fit 关节缺少 Maya 标签。面板的“兼容导出原版 Fit”选项可从嵌套容器只读生成文档，按名称在文档里补齐缺失标签；在空场景导入后，41 个关节、Root 高度偏移和文档语义一致。导入的新 Fit 可通过完整角色用例一次构建并登记 74 个 Body 关节、Arm／Leg／Torso／Global／双侧 Hand 控制；单次 Undo 移除角色而保留 Fit，Redo 和保存重开恢复。在保留原版 Fit 的隔离副本中，面板的“按关节名补全缺失标签”选项也能只给新 Body 推断标签，不改写原 Fit。原版多 Cup、Jaw、JawEnd，手指命名为 `IndexFinger1`～`IndexFinger4` 等，Ring／Pinky 从 Cup 分支生长；Hand 规划器识别这套命名和父链，生成 30 个手指 FK 控制，逐个通过实际关节驱动和撤销。原版 18,151 顶点网格的静态副本可绑定 74 个 Body 关节；总控平移使网格顶点同步移动，Undo 恢复，临时文件保存重开后 Skin 影响关节保留。右食指控制器第 1～5 帧动画通过保存重开；74 关节发布骨架完成 5 帧烘焙，FBX 重新导入 Maya 后得到 75 个关节（含 Root Motion），食指动作保留。Fit 文档路径解决了旧 Rig 同名冲突，但尚未迁移原网格与原权重；FBX 仅含发布骨架，不含网格。原文件未被写入。

原版网格的 Skin 为 18,151 个顶点、121 个影响关节，逐顶点权重和的最大误差约 `5.7e-13`。其中 53 个影响关节与当前 74 关节 Body 同名，另 68 个辅助／分段关节承载总权重质量的 41.40%（7,514.81 个等效全权重点），主要落在脊柱、肩、髋、肘分段。按同名直接导入会丢失这部分权重；不能把新建 Closest Distance 蒙皮视为原版权重保留。下一步必须保留这些辅助变形关节及其驱动，或完成逐顶点、逐姿态对照的等价重映射。

## 当前下一步

1. 修复 CO-05 肩胛在 IK 模式的 Z 轴残差，扩展到手部与公开示例角色，并用三轴及混合旋转核对实际 Body 动作。
2. 用原版 `sam.mb` 对照 CO-06／CO-07 轴结果及 Mirrored Behavior 组合；完善控制器类型映射，并完成 Control Orient 可见 Maya 验收。
3. 继续登记 Custom Controllers 和其他栏目公开操作来源。
4. 将原版网格与 Skin 安全带入 Fit 文档创建的新角色场景；为 68 个有权重的辅助／分段关节建立变形保留方案，并以原权重和动作后的顶点位置验收，再处理网格发布与 Maya 可见全链路。
5. 更新主页封面与仓库展示，只使用真实 Maya 绑定结果、骨骼、控制器和层级截图。
