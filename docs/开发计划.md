# 开发计划与当前缺口

更新日期：2026-09-30。目标是以 Python 复刻 AdvancedSkeleton 6.925 的 Maya 行为与界面入口；内部结构允许重组，功能和结果须逐项对照原版。原 MEL 位于本机只读参考目录，不纳入本仓库。

## 开发轮次硬性门禁

每轮至少进行 30 分钟实际开发，只有整个复刻开发真正完成才能提前结束。开轮记录 UTC 开始时间，结束前再读取并核算；未满 1800 秒继续开发核心代码。不能把写计划、查阅、汇报、等待或静态检查冒充连续开发，也不能用人为拆分的“本轮切片”作为提前结束理由。一次提交、一个局部功能、一条小链路完成或某个分支遇阻，均须接着开发其他核心功能，不能当作收工点。30 分钟只是最低时长，不是停止开发的目标。当前先连续补全内部 Python 逻辑，集中做必要的静态检查；真实 Maya 整链测试放到核心代码齐备之后。详见[Codex Goal 提示词](CODEX_GOAL_快速开发.md)。

## 当前结论

2026-09-30 新增原版 HeadSquash 的创建、删除、Optimize 与 Include selected：四个控制器、2×11×2 晶格、十关节 Skin、五个样条簇、Main／Head 缩放补偿、拉伸与体积网络均接到宿主和原栏目。黄色控制器按原版在晶格定位后加入；变形器创建临时关闭 component tags 后恢复选项。追加／删除同时维护 Face 姿态与 FaceAllSet，Delete Face 清理内部晶格 Skin 和生成的变形集，保留脸部生产 Skin。Face 主体改用原版 FaceGroup 下的 Motion／Deformation 层级、JawFollow、SideReverse、控制分组和中性模板层，补五种 Lambert 材质。另新增 asFaceFitJawCurves／asCurveOffsetMesh 对应四条持久 Jaw 参考曲线与网格法线贴合，入口位于 Face / Build ...；这不是完整 Jaw 权重或嘴部绑定。均为代码接入、Maya 未验收。

2026-09-30 主构建继续按 MEL 修正：Root 准备后再解析真实脊柱父链；预构建统一名称、标签、缩放和朝向的顺序；缩放使用原版拆父级、恢复单位缩放、乘回容器缩放、重挂父级的流程。朝向与脊柱 IK 从真实标签解析，不再由名称推断；朝向前执行中心 IK 链吸附，worldOrient 保留 MEL 的固定世界 Y／Z 规则，并允许在 Z-Up 场景中进行原版预构建更新。旧 Fit 缺失 OPM／Sub／Extra 时按原版关闭。仅 FK 躯干贯通角色登记、读回与同布局重建；无 Inbetween 分段的 unTwister 标记按原版保留但不启用，不再拒绝整个 Fit 输入。以上为代码接入，Maya 未验收。

本批继续对照 MEL 补入原版 `asFaceCtrlBox/asFaceCreateCtrlBox` 的 12 个滑块、可见性和限位属性、Phonemes／Emotions／ARKit／Roblox／SnapChat 图标及区域图形；`asCreateFaceFit` 的 21 类球形定位点、UpMidLo、Tongue Fit 与十套 Fit 材质；`asFaceTongue` 的控制／关节链、矩阵或约束驱动、Jaw 跟随、立方体分段权重构造与向舌头模型的权重复制。新增入口已接到 Face 的 Fit 与 Build 栏目，新增生成节点追加到 FaceAllSet，正式模型 Skin 不列为可直接删除的模块资产。以上是代码接入，Maya 未验收。

仍有明确衔接缺口：旧眼睑流程的 `ctrlEye_R/L` 与原版 ctrlBox 滑块同名，目前构建前拒绝冲突，不能先运行旧眼睑再叠加原版控制盒；完整 Face Build 阶段编排尚未完成。Lip Outer/Main/Inner Fit、完整 Lip／Jaw 权重与 Regions 驱动仍需继承原版。Tongue 构建沿用原版的 Lip Main、Tongue 输入与 Jaw 层级前提，当前纯 Python 新场景还不能仅靠上述新增入口完成完整脸部。Face Jaw Fit 遇到已有 Body Jaw 会明确要求先移除，原版自动移除 Body Jaw 的调用仍需接入。不得将这些分支的代码接入记为完整 FaceSetup 已完成。

**尚未完成全量复刻。** 标准 Fit 到 Body、控制器、新 Skin、动画和 FBX 有过 Maya 运行基线；当前 HEAD 在这些验收之后又改动了 Fit Part、Inbetween、控制器层级、选择集和重建等主链，因此历史通过不能证明当前版本可用。原版公开操作清单仍不完整，不给出整体完成百分比。详见[功能覆盖矩阵](功能覆盖矩阵.md)和[历史验收记录](历史验收记录-v0.96.md)。

Skin 主链目前已读取 Maya Smooth Bind 的绑定、归一化、计算、权重分布及最大影响数选项；拓扑重绑来源资产增加逐顶点 Weight Blended 数据，普通表面转移也把它和关节权重一次写回。非归一化 Skin 的原始权重总量已贯通文档、表面转移、拓扑重绑、跨段数脊柱迁移以及原版角色的密集权重迁移；原版角色迁移还带上绑定方式、蒙皮算法、分布方式、Blend Weight 和 Envelope。Geodesic Voxel 的 geomBind 参数也已加入捕获和重建。FBX 发布临时 Skin 保留权重分布及真实影响关节索引，并核对克隆网格拓扑；曲线脊柱 IK 匹配已纳入逐控制器缩放求解。这些新增路径只完成 Python 代码和静态语法检查，尚未运行 Maya，尤其 Geodesic Voxel 必须在有 GPU 的 Maya 图形环境下验证。

最新主链对照补了原版 FKX 对关节位置的驱动：通用 FK、五指、标准臂腿及躯干非根控制增加位置约束，Root Body 的位置来源改为 Root FKX；手脚 IK/FK 输出混合现在覆盖整条标准链。躯干连接只给需要的 IK 机制起点另设位置来源，避免与 FKX 同时占用 FK 机制关节的位置通道。旧角色重建读取新旧位置约束布局并核对来源与目标。以上仅为代码接入，当前版本尚未经过 Maya 整链验收；下一次集中验收须重点观察肩、髋、脚趾的 FK 位移及切换姿态。

固定与可变脊柱的 FK 机制根已从 Base FK 的实际朝向接收层获取位置，Fit Inbetween 改接后仍沿同一接收层驱动；旧角色的 Pelvis 来源由保存角色策略读取并保留。重建现在检查通用 FK 点／朝向约束的来源与三轴输出，Skin 拓扑重绑保留原 Skin 的绑定方法、归一化方式、计算方法及 Envelope 值或驱动连接。Inbetween FK／IK Body 与下游 FK 跟随约束也回读输出接线。这些是代码接入和静态检查，当前版本未做 Maya 整链验收。

拓扑重绑来源资产现额外携带 Skin 绑定拓扑摘要，执行前必须与待替换 Skin 的原绑定拓扑一致；没有该摘要的旧版来源资产只能用于普通表面转移，重绑须从旧拓扑重新导出。替换 Skin 时也恢复 Envelope 驱动和原有选择集归属；遇到自定义 Skin 属性则预先拒绝，避免静默丢失。该格式兼容旧文件读取，但重绑门禁更严格。代码尚未经过 Maya 实景验证。

本轮继续沿主构建补代码：原版脚部 Heel／BigToe／PinkyToe 临时 Body 标记在 Foot 控制定位之后、角色登记和 Skin 之前删除，并同步骨架归属计数；已有旧角色的重建保留其原有标记拓扑。FBX rig 构建也移除这些临时关节和对应的空壳 FK 控制器，从来源动画转接及 FK 曲线尺寸投影中排除对应的已删变形目标，并让 IK/FK 切换同步 FK 曲线可见性。面板在未找到 Fit 且只选中一个来源根关节时，按原版将所选关节树直接纳入 Fit 后构建；不再自动复制和推断标签。公开构建入口补上原版厘米单位门禁。以上均为代码阶段，尚未经过真实 Maya 验收。

通用附加 Fit 分支已进入 Body 主构建、FK 层级、缩放与分段补偿、登记及重建策略；创建后回读控制层与约束。来源骨架中仅左侧存在的附加分支现可沿父链带入普通子关节，并按原版 `noMirror/noMirrorLeft` 规则定位到最终左侧 Body。当前仍属于代码接入，未经 Maya 验收，不能据此宣称任意附加骨架已经完成复刻。

通用 FK 的 OPM 跟随与原版矩阵相乘次序、Main 缩放补回已接入；通用 Twist 在控制层生成后由静态参照改接真实 FK 来源。Bendy 标准链保留原构建阶段，依赖通用 FK 的连通链延后建立，并为无可见 FK 的末端建立独立参照；参照在标准父骨段下跟随 FK／IK 混合矩阵。通用 Bendy 缩放与重建时的新旧连接布局也已接入。以上均未在 Maya 验收，仍须核对真实姿态和变形。

Bendy 主控进一步按原版改用起点／终点 Bend 控制矩阵的位置混合与半强度 aimMatrix，父级从独立 Part Twist 来源抵消轴向扭转；无相邻 Bendy 子段的末端也改为下游位置和本段朝向合成。主控、Bend0、末端参照和 Micro 在新构建中按已朝向 Body 的起点框架定位，非对称来源沿原版采用反向瞄准轴。保存角色的旧约束、来源、末端和朝向布局由重建策略识别保留。代码接入仍需当前 Maya 整链验收，不能视为形态或运动已等价。

最新 Bendy 对照已补齐原版剩余 Part 局部长度权重、Maya 版本对应的曲线参数模式，以及 OPM／非 OPM 两条 Micro 缩放接线；新建 OPM 角色保留关节原有缩放来源，仅将 Bendy 乘积送到 MicroOffset，保存角色按标记恢复各自布局。Fit twistJoints 数量不再使用原版没有的上限。代码尚未经过真实 Maya 验收。

本轮对照原版 `Geometry` 规则补上构建时自动收纳 `geo`、按网格 UUID 跟踪蒙皮目标，以及重建时保留用户模型子树、容器的原生变换／显示值和自定义属性。若用户对象藏在同时重建的生成分支下，也在替换前移出再挂回；同名无法区分或受引用／锁定的情况明确拒绝，避免静默删模型。Delete Adv 同样先移出生成分支内的用户模型。Geodesic Voxel Skin 改为按 Maya 自带流程先建普通 Skin，多个网格合并做一次体素求解，再移除无权重影响关节。以上只完成 Python 代码与语法检查，尚未运行当前版本 Maya。

后续代码已把 Geometry 原生属性的输入、输出、独占单位转换及 `offsetParentMatrix` 纳入重建交接，保留旧容器的连接边界与动画采样；用户自定义矩阵属性也按 16 个数值完成捕获、复制和采样。FBX 临时 Skin 现复制原 Skin 的计算选项和绑定逆矩阵，烘焙网格世界变换，并在输出前逐采样帧比对来源与克隆网格顶点及额外影响关节；复制网格上残留的变换输入会在绑定帧断开并冻结。上述均为代码接入，当前 Maya 尚未验收；其他多节点 Geometry 驱动图及 FBX 重导入后的等价性仍有缺口。

生产变形器连接旧 Rig 的直接边和两侧独占 `unitConversion` 已进入重建暂存、所有权审计、交接与删除后复检。导出骨架的实时关节现读取来源 `offsetParentMatrix`；烘焙改按来源关节的世界矩阵逐帧生成独立平移／旋转／缩放曲线，断开偏移矩阵输入，并复检关键帧世界姿态及独立性。以上仍未运行 Maya，不能据此宣称包含 OPM、生产变形器的角色重建和 FBX 已通过。

后续补上 Fit Part 扭转构建前的四元数运行环境准备、共享单位转换节点多目标扇出交接、FBX 导出前最后一次 Skin 等价复检。Skin 和生产变形器的原生动画曲线现在沿 Maya 常见数值混合节点向上查找，复用完整曲线快照记录关键帧、切线、锁定、breakdown 与循环边界，重建交接前后核对，并用关键帧及区间中点采样变形。Skin 变形集的顶点成员范围进入角色保留快照和重建复检，FBX 临时 Skin 也复制这一范围。这些是代码接入，仍待集中 Maya 整链验收；任意用户自定义工具节点的动画网络尚未声明覆盖。

新建 Skin 的构建后快照现检查全部顶点均在原生变形集中；FBX 临时导出在复制后和真正导出前都复核来源、克隆两侧的成员范围。表面来源资产升级为带顶点成员的版本；局部 Skin 拓扑重绑和表面权重转移沿同一三角形投射成员范围，在写权重前临时扩展目标变形集，写完再用可撤销的 Maya `sets` 命令写回目标成员。旧版来源资产没有成员数据时，拓扑重绑明确要求重新导出；以上代码仍待真实 Maya 验收。

拓扑重绑还回读并迁移原 Skin 的绑定逆矩阵、矩阵驱动，以及 `useComponents`／法线／双四元数计算选项及其驱动；新旧影响关节按实际逻辑索引重新匹配。局部变形集边界的目标权重只混合来源中真正受 Skin 影响的顶点。软选择式的非单位变形集成员权重仍没有无损资产格式，当前在捕获时明确拒绝。以上仍是代码阶段，未经 Maya 验收。

“代码已接入”指 Core、应用层、Maya 宿主及入口之间存在调用路径；“Maya 已验收”须有当前实现的真实场景结果。独立计划、宿主接口、面板占位或旧版测试都不计为行为完成。

## 下一阶段工作顺序

每轮 Goal 从 UTC 开始计时，连续进行至少 1800 秒实际核心开发；除整个复刻完成外，任何单项提交、局部完成或受阻都不能提前结束。详见 [Codex Goal 提示词](CODEX_GOAL_快速开发.md)及仓库 `AGENTS.md`。时间门槛是下限，不能把下一段工作拆成几个几分钟的轮次。

1. 连续完成标准 Fit → Body／Part → 控制器和驱动 → Skin 的原版逻辑与真实调用交接。优先修影响构建和重建的数据丢失、错接和参数分支；对照 MEL 只为确认要写的行为，不另开外围研究。
2. 在同一主构建上继续完成保存重开、旧角色数据捕获与同拓扑重建，再接动画和 FBX 发布；重建不复制另一套 Body／Rig 生成架构。一个分支完结即推进下一项 P1 缺口，不以“本轮切片”收工。
3. 代码主链齐备后一次集中 Maya 验收，覆盖公开 Sam、差异骨架、双 Skin、保存重开、重建、写键和 FBX。当前阶段不启动 Maya，也不逐函数频繁测试；静态语法及差异检查集中在成批修改后进行。
4. 再按覆盖矩阵完成 P2～P4。Blender 仍属第二阶段。

本计划取代了曾不断追加阶段结果的长日志。旧分析、历史测试数据与原先的判断保存在[历史开发计划记录](历史开发计划记录.md)，其中“尚未实现”及“下一步”等陈述只表示当时状态，不能作为当前代码结论。当前开发 Goal 保留一份：[CODEX_GOAL_快速开发](CODEX_GOAL_快速开发.md)。本地开发不推送 GitHub。
