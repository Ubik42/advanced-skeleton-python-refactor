# 四肢动画开发记录

标准身体动画的左右臂腿双向转换已通过。后续已补齐动态拉伸与体积匹配，见 [拉伸与体积动画匹配](拉伸与体积动画匹配.md)；完整动画工作包仍包含待完成的空间切换。

## 登记与动画通道

`EnableBodyCharacterLimbAnimation(host).plan()` 只读生成扩展计划，`.apply()` 显式升级已登记角色。新增 8 个 FK 机制骨段长度通道与 24 个 IK 朝向补偿通道，完整通道数从 157 / 261 增至 189 / 293。姿态和动画快照包含这些数据；兼容摘要随布局变化，旧布局文档不会被当作完整的新布局。

长度通道由既有四肢匹配计划解析真实驱动关节和有符号主轴。身体快照新增世界缩放，IK→FK 将世界骨段投影长度换算为本地平移，避免 Global 缩放被重复应用。控制器匹配只写目标平移和旋转，保留自身缩放。

每侧上、下段分别有 XYZ 朝向补偿，保存在四肢 settings 节点。独立 multiplyDivide 将补偿乘以现有 FK/IK blend：FK 端点无补偿，IK 端点应用完整补偿；显式单位转换节点负责 degree 与 Maya 内部弧度。FK→IK 用原身体朝向与新求解朝向的四元数差求补偿。静态匹配和动画转换共用这套路径，原 Body 层级及约束目标保持不变。

登记恢复审计补偿节点类型、归属、乘法模式、单位换算系数、全部接线与输出消费者，拒绝外部共享。原生曲线允许 Maya 隐式场景时钟；显式非时间输入仍拒绝。Maya Undo 遗留的尾部空 message 数组槽可保留，额外有效连接仍拒绝。

## 调用

```python
from adv_py.adapters import MayaBodyBuildHost
from adv_py.application import EnableBodyCharacterLimbAnimation, BakeBodyCharacterLimbMode

host = MayaBodyBuildHost()
EnableBodyCharacterLimbAnimation(host).apply()
BakeBodyCharacterLimbMode(host).execute(1, 21, "arm", "R", "ik", step=1)
BakeBodyCharacterLimbMode(host).execute(1, 21, "leg", "L", "fk", step=1)
```

目标部位为 arm / leg，侧别为 R / L，模式为 fk / ik。源 blend 必须位于端点，采样帧、曲线归属、时间单位与事务边界沿用全身动画合同。每笔转换暂时释放原曲线，将数值交给静态匹配器，采集完整身体矩阵通过后才批量写键；失败恢复原曲线和连接。保证范围为明确采样帧，不承诺点间运动保持。

## 验收证据

- 308 项纯 Python 回归通过，包括世界缩放下的臂腿本地长度、有符号主轴和退化缩放拒绝。
- 30 / 70 关节场景均覆盖左右臂腿 FK→IK 与 IK→FK，包含 Global 平移、旋转和 1.0–1.2 倍等比缩放。标准场景最大网格位置分量误差约 `3.58e-6 cm`。
- 登记扩展只读预演、原动画与蒙皮保留、整笔 Undo / Redo、重复调用无修改、补偿图和新增属性撤销清理、登记失败回滚通过。
- 70 关节转换曲线 Undo / Redo、补偿匹配中注入异常后的完整恢复通过。新进程重开后，身体矩阵最大元素误差约 `3.50e-6`，蒙皮误差约 `3.58e-6 cm`，仍可继续双向转换；非法补偿输出消费者被拒绝。
- 既有四个静态臂腿匹配 smoke 通过；既有脊柱动画保存重开与继续转换回归通过。

完整入口为 `validation/maya_character_limb_animation_smoke.py`，输入为已有标准动画场景的结果目录与新报告路径。`--reopen` 检查同报告名保存的场景；`--registration-only` 仅检查登记合同，不能替代完整转换验收。新运行结果不进入版本库。

## 动态拉伸缺口与后续实现

将第 11 帧右臂的两段 FK 长度同时增加 15% 后，FK→IK 的完整身体复检仍失败并正确回滚，最大矩阵元素误差约 `0.238`。IK 自动拉伸以起点到目标的距离决定长度，而弯曲的已拉伸 FK 链需要额外控制两段实际长度；仅保留 FK 长度和末端位置还不够。后续通过独立 IK 段长覆盖与 volume 匹配因子解决，并用双侧臂腿拉伸、膝盖锁定、脚掌滚动和辅助骨骼实际蒙皮验证，阈值保持不变。实现及证据见 [拉伸与体积动画匹配](拉伸与体积动画匹配.md)。
