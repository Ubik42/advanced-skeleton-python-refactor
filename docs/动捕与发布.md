# 动捕与骨架发布

当前 MoCap 入口按显式的来源关节与 Body 关节映射建立临时约束，再把采样姿态烘焙到 Body。FBX 入口只导出已烘焙的独立导出骨架，导出前检查范围、来源依赖和目标文件占用。

映射预设由来源/目标关节短名、平移与旋转传递开关、预期 Body 关节数组成，不固化 Maya 命名空间。文件采用版本化 JSON 和内容摘要，保存时不覆盖同名文件；读取后仍需针对实际动捕源和 Body 执行 `InspectMocapBodyMapping`，由其检查根关节、拓扑与动画通道。`maya_mocap_mapping_smoke.py` 在 30 关节 Body 和 `TakeA` 命名空间动捕源上确认保存重读后的五项解析计划完全相同。

```python
from adv_py.application import InspectMocapBodyMapping, load_mocap_mapping_preset

preset = load_mocap_mapping_preset(r"D:\mocap\human.json")
plan = InspectMocapBodyMapping(host).execute(
    "|TakeA:Hips", preset.mappings,
    expected_body_joint_count=preset.expected_body_joint_count,
).require_valid()
```

外部 FBX 不直接导入当前角色场景。`ImportMocapFbx` 先在独立后台 Maya 进程中读取 FBX，把单根关节骨架、直接动画曲线、场景单位、切线类型与角度、加权切线参数、曲线循环设置，以及关键帧和相邻关键帧中点的世界矩阵写成受限片段；主场景校验片段后在新命名空间重建关节与曲线，并在采样时刻比对世界矩阵。文件解析失败不会改变当前场景；场景写入失败会回滚，成功写入可以单次撤销和重做。

```python
from adv_py.adapters import MayaMocapClipHost
from adv_py.application import ImportMocapFbx

imported = ImportMocapFbx(MayaMocapClipHost()).apply(
    r"D:\mocap\take_01.fbx", namespace="Take01",
)
source_root = imported.snapshot.root
```

`maya_body_fbx_export_smoke.py` 将自生成 FBX 作为外部动捕导入，验证 31 关节的关键帧及帧间中点姿态，另验证失败注入、单次撤销、此前撤销历史、重做与保存重开。`maya_long_mocap_fbx_smoke.py` 对 1101 键单关节 FBX 验证整条曲线保留，并将世界姿态验收均匀限定为 2000 个时刻，覆盖首尾与帧间。当前入口只接受单根骨架和直接连接的原生时间动画曲线；对约束驱动、多根骨架、复杂 FBX 层与长片段的多关节规模仍需单独验收。

角色根部动捕可通过 `RetargetMocapRootToCharacter` 写入已登记角色的 Global 控制器。校准帧记录来源根关节世界矩阵；每个采样帧取其相对校准帧的刚体变化，把同一变化应用到该帧角色原有根部姿态，并求出 Global 控制器的六个平移、旋转通道。来源和目标无需处于相同世界位置；原有其他控制器曲线保持不变。输入必须是经过关节来源审计的动画骨架，采样区间须落在来源键值范围内。这个入口仅写入根部；躯干和四肢使用下述组合入口。

```python
from adv_py.adapters import MayaMocapControlHost
from adv_py.application import RetargetMocapRootToCharacter

samples = RetargetMocapRootToCharacter(MayaMocapControlHost()).apply(
    "|TakeA:Hips", start_frame=1, end_frame=10, sample_by=1,
)
```

`maya_mocap_control_root_smoke.py` 在自生成角色和动捕源上验证 10 帧 Body 根部世界矩阵、六条可编辑控制曲线、已有全局与躯干动画下的其他控制通道不变、失败回滚、单次撤销重做与保存重开。`maya_mocap_control_namespace_smoke.py` 在同场两个角色上验证只修改指定命名空间的角色。

标准双段脊柱可用 `RetargetMocapSpineToCharacter` 一次写入根部与 Spine FK 控制曲线。来源须明确指定根、脊柱、胸部三段直接父子链；校准帧上的来源局部旋转作为零点，各采样帧的局部旋转变化叠加到角色原有 FK 脊柱姿态。写入要求采样帧处于 Spine FK 模式；IK 或混合姿态尚需单独求解。这个入口只处理标准双段 Spine；四肢和头颈使用下述组合入口。

```python
from adv_py.application import RetargetMocapSpineToCharacter

root_samples, spine_samples = RetargetMocapSpineToCharacter(MayaMocapControlHost()).apply(
    "|TakeA:Hips", source_spine="Spine", source_chest="Chest",
    start_frame=1, end_frame=10,
)
```

`maya_mocap_control_spine_smoke.py` 验证三关节来源、10 帧 Global 与两个 Spine FK 控制、已有 FK 动画叠加、Body 世界矩阵、其他通道不变、故障回滚、单次撤销重做及保存重开。

`RetargetMocapFourLimbsToCharacter` 在一次事务中写入 Global、标准双段 Spine FK、左右手臂与左右腿 FK 控制曲线。每条四肢来源按近端、中段、末端三个直接父子关节指定；校准帧的局部旋转作为零点，目标保留原有骨段长度和未纳入映射的控制曲线。写入区间需要处于对应四肢的 FK 端点；来源关节的平移、比例与 IK 目标不通过该入口转移。完整映射实例：

```python
from adv_py.application import MocapLimbSource, RetargetMocapFourLimbsToCharacter

limbs = (
    MocapLimbSource("arm", "R", "Shoulder_R", "Elbow_R", "Wrist_R"),
    MocapLimbSource("arm", "L", "Shoulder_L", "Elbow_L", "Wrist_L"),
    MocapLimbSource("leg", "R", "Hip_R", "Knee_R", "Ankle_R"),
    MocapLimbSource("leg", "L", "Hip_L", "Knee_L", "Ankle_L"),
)
root, spine, four_limbs = RetargetMocapFourLimbsToCharacter(MayaMocapControlHost()).apply(
    "|TakeA:Hips", source_spine="Spine", source_chest="Chest",
    source_limbs=limbs, start_frame=1, end_frame=10,
)
```

`maya_mocap_control_four_limbs_smoke.py` 在 30 与 70 关节自生成角色上验证 10 帧四肢 Body 世界矩阵和 FK 曲线、区间外旧键保留、第三条四肢写入失败后的整体回滚、单次撤销重做与保存重开。

`RetargetMocapUpperAndFourLimbsToCharacter` 在上述事务中增加 Neck、Head、左右 Scapula 的 FK 旋转。来源必须形成 Chest→Neck→Head 和 Chest→Scapula→Shoulder 的直接父子链；目标使用标准 Body 的对应关节及已登记 FK 通道。带头部瞄准的角色要求所有采样帧的 `headAim` 权重为零。这个入口将来源相对校准帧的局部旋转变化写到角色控制器，保留角色骨段长度及未映射控制曲线。

```python
from adv_py.application import RetargetMocapUpperAndFourLimbsToCharacter

root, spine, upper, limbs = RetargetMocapUpperAndFourLimbsToCharacter(
    MayaMocapControlHost()
).apply(
    "|TakeA:Hips", source_spine="Spine", source_chest="Chest",
    source_neck="Neck", source_head="Head",
    source_scapula_right="Scapula_R", source_scapula_left="Scapula_L",
    source_limbs=limbs, start_frame=1, end_frame=10,
)
```

同一脚本的 `--upper` 验收在 30 与 70 关节角色上核对 10 帧的头颈、肩胛和四肢世界矩阵、控制曲线、旧键、失败回滚、撤销重做及重开。手指、脚趾，以及 Spline/IK 控制器尚未纳入该整段转移。

外部 FBX 与版本化映射预设可以连用。预设的 15 条映射必须准确覆盖 Root、Spine1、Chest 和左右四肢三段：Root 同时传递平移与旋转，其余只传递旋转；导入后仍会按当前来源骨架与角色 Body 验证拓扑及关节数量。导入和角色写入是两次可分别撤销的操作，导入成功而映射失败时动捕骨架保留在场景中，修正预设后可重试写入。

```python
from adv_py.adapters import MayaMocapClipHost, MayaMocapControlHost
from adv_py.application import ImportMocapFbx, RetargetMocapFourLimbsToCharacter, load_mocap_mapping_preset

imported = ImportMocapFbx(MayaMocapClipHost()).apply(
    r"D:\mocap\take_01.fbx", namespace="ExternalTake",
)
preset = load_mocap_mapping_preset(r"D:\mocap\control_mapping.json")
root, spine, limbs = RetargetMocapFourLimbsToCharacter(MayaMocapControlHost()).apply_with_preset(
    imported.snapshot.root, preset, start_frame=1, end_frame=10,
)
```

`maya_fbx_to_character_controls_smoke.py` 使用自生成 15 关节 FBX，完成隔离导入、预设保存重读与审计、10 帧角色控制曲线写入、无效预设拒绝、两次撤销重做及场景重开。该验收证明这类直接关节动画能走通完整链路；复杂 FBX 动画层、非常规骨骼拓扑与约束驱动仍在边界外。

头颈与肩胛版本的预设准确覆盖 19 个目标关节：上面的 15 个关节加 `Neck_M`、`Head_M`、`Scapula_R` 和 `Scapula_L`。根部传递平移和旋转，其余关节只传递旋转。导入后的调用形式与 15 关节版本相同，只需使用 `RetargetMocapUpperAndFourLimbsToCharacter(...).apply_with_preset(...)`；返回值额外包含 `upper` 采样。`maya_fbx_to_character_controls_smoke.py --upper` 已验证 19 关节 FBX、预设往返、Body 姿态、两次撤销重做及重开。

标准全身 FK 入口 `RetargetMocapFullFkToCharacter` 在头颈、肩胛和四肢之上继续写入双脚 `Toes`；70 关节角色还写入双手五指各三节的 FK 控制器。30 关节角色的预设准确覆盖 21 个目标关节，70 关节角色准确覆盖 51 个；末端来源必须与脚踝、手腕及指节构成对应的直接父子链。根部传递平移与旋转，其余关节只传递旋转；脚趾写入要求双腿处于 FK 模式。来源的指尖 `End` 和脚趾末端没有独立控制器，不纳入映射。

```python
from adv_py.application import RetargetMocapFullFkToCharacter

root, spine, upper, limbs, distal = RetargetMocapFullFkToCharacter(
    MayaMocapControlHost()
).apply_with_preset(imported.snapshot.root, preset, start_frame=1, end_frame=10)
```

`maya_mocap_full_fk_smoke.py` 对 30／70 关节角色验证末端姿态、控制曲线、区间外旧键、末端写入故障回滚、单次撤销重做及保存重开；`maya_fbx_to_character_controls_smoke.py --full` 对 21 关节 FBX，`--full --hand` 对 51 关节 FBX 验证隔离导入、预设审计、控制曲线、两次撤销重做与重开。该 FK 入口限标准双段 Spine FK 和四肢 FK；四肢 IK 使用下述组合入口，脊柱 Spline IK 及复杂 FBX 动画层尚未覆盖。

同一套 21／51 关节映射也可写入四肢 IK 控制器。`RetargetMocapFullLimbIkToCharacter` 在一次事务里先生成全身 FK 动画，再逐帧匹配左右手臂和左右腿的 IK 目标、Pole、长度与朝向辅助通道；脊柱、头颈、肩胛、脚趾和手指仍由 FK 控制。角色须预先执行 `EnableBodyCharacterLimbAnimation`，使长度与朝向辅助通道进入登记。IK 解算的采样帧世界矩阵误差上限为 `1e-3`；这是本入口的验收界限，不代表稀疏采样帧间的曲线完全一致。

```python
from adv_py.application import EnableBodyCharacterLimbAnimation, RetargetMocapFullLimbIkToCharacter

EnableBodyCharacterLimbAnimation(MayaMocapControlHost()).apply()
root, spine, upper, limbs, distal, conversions = RetargetMocapFullLimbIkToCharacter(
    MayaMocapControlHost()
).apply_with_preset(imported.snapshot.root, preset, start_frame=1, end_frame=10)
```

`maya_mocap_full_fk_smoke.py --ik` 在 30／70 关节角色上验证四肢模式、全身姿态、区间外旧键、末端与第三条 IK 转换故障回滚、单次撤销重做及重开；`maya_fbx_to_character_controls_smoke.py --ik` 与 `--ik --hand` 验证真实 FBX 导入到四肢 IK 控制曲线的完整链路。当前 IK 入口要求来源片段覆盖写入区间、角色四肢起始为 FK 端点，仍不处理脊柱 Spline IK、混合模式或来源约束与动画层。

标准双段脊柱也可在同一事务中转换到 Spine IK。`RetargetMocapFullIkToCharacter` 先写入全身 FK，再匹配 Spine IK，最后匹配四肢 IK；头颈、肩胛、脚趾和手指继续由 FK 控制。角色同样需要先启用完整四肢动画通道登记，采样区间的 Spine 和四肢须从 FK 端点开始。调用返回额外的脊柱转换片段：

```python
from adv_py.application import RetargetMocapFullIkToCharacter

root, spine, upper, limbs, distal, limb_conversions, spine_conversion = (
    RetargetMocapFullIkToCharacter(MayaMocapControlHost()).apply_with_preset(
        imported.snapshot.root, preset, start_frame=1, end_frame=10,
    )
)
```

`maya_mocap_full_fk_smoke.py --spine-ik` 在 30／70 关节角色上验证 Spine 与四肢 IK 模式、采样姿态、区间外旧键、脊柱与第三条四肢转换中途失败后的整体回滚、单次撤销重做及重开；`maya_fbx_to_character_controls_smoke.py --spine-ik` 与 `--spine-ik --hand` 验证 21／51 关节 FBX 完整链路。Body 采样帧世界矩阵误差上限仍为 `1e-3`。可变脊柱的 Spline IK 使用下述入口；混合模式、复杂动画层及帧间曲线等价性仍需单独实现和验收。

可变脊柱使用独立的登记驱动计划。`RetargetMocapVariableFullFkToCharacter` 根据角色实际轴向关节数生成 Spine FK 控制组，再依次写入头颈、肩胛、四肢、脚趾和已有五指。映射预设须准确覆盖这些有独立 FK 控制器的关节，并保持所有来源与目标的直接父子关系；根部传递平移和旋转，其他关节只传递旋转。单段脊柱的 29 关节角色要求 20 条映射；四段脊柱的 32／72 关节角色分别要求 23／53 条；八段脊柱的 36 关节角色要求 27 条。

`RetargetMocapVariableSplineIkToCharacter` 在同一事务内将上述 FK 脊柱动画逐帧拟合到 Spline IK；`RetargetMocapVariableFullIkToCharacter` 继续把四条四肢链匹配到 IK，手指和脚趾仍保持 FK。调用 Spline IK 前须执行 `EnableBodyCharacterSplineAnimation`；调用全身 IK 还须执行 `EnableBodyCharacterLimbAnimation`。两个入口均要求对应模式在写入区间起始为 FK 端点。

```python
from adv_py.application import (
    EnableBodyCharacterSplineAnimation, EnableBodyCharacterLimbAnimation,
    RetargetMocapVariableFullIkToCharacter,
)

EnableBodyCharacterSplineAnimation(host).apply()
EnableBodyCharacterLimbAnimation(host).apply()
root, groups, spline_conversion, limb_conversions = (
    RetargetMocapVariableFullIkToCharacter(host).apply_with_preset(
        imported.snapshot.root, preset, start_frame=1, end_frame=10,
    )
)
```

`maya_mocap_variable_fk_smoke.py` 已在自生成的单段、四段、四段带五指、八段角色上验收全身 FK、Spline IK、Spline＋四肢 IK，以及对应真实 FBX 隔离导入；检查控制曲线、采样帧 Body 世界矩阵、旧键、部分组及 IK 转换失败回滚、撤销重做和重开。四段／八段角色的全身 IK 矩阵误差低于 `1e-3`。八段脊柱较小的非零逐节弯曲可拟合，较大的逐节弯曲超过现有曲线表达残差门限时会拒绝并恢复原角色。可变脊柱的任意来源动作并无可拟合保证；复杂动画层、长片段多关节规模和帧间曲线等价性仍需单独验收。

`RetargetMocapVariableMixedToCharacter` 要求明确指定脊柱及四条四肢的 `fk`／`ik` 模式。它先写完整 FK 控制曲线，再在同一个事务中只转换选定的 IK 部位；保留未选部位的 FK 曲线与模式。下例将右臂和左腿转为 IK，脊柱、左臂和右腿保留 FK：

```python
mixed = RetargetMocapVariableMixedToCharacter(
    host,
    spine_mode="fk",
    limb_modes={
        ("arm", "R"): "ik", ("arm", "L"): "fk",
        ("leg", "R"): "fk", ("leg", "L"): "ik",
    },
)
root, groups, spine_conversion, limb_conversions = mixed.apply_with_preset(
    source_root, preset, start_frame=1, end_frame=10,
)
```

四段角色的两种固定混合配置（脊柱 FK／IK）及真实 FBX 隔离导入均已在后台 Maya 运行。验证包含 10 帧身体世界矩阵、模式值、旧键、部分写入失败回滚、单次撤销重做与保存重开；最大矩阵误差约 `5.9e-4`。脊柱 IK 仍须先启用 Spline 动画通道，任何四肢 IK 都须先启用四肢动画通道。

`RetargetMocapVariableScheduledToCharacter` 接受从首个采样帧开始的模式事件。事件帧必须落在动捕采样序列中；下例在第 5 帧将脊柱改为 IK、第 8 帧改回 FK，右臂在第 3–6 帧使用 IK，右腿从第 6 帧起使用 IK。未列出更多事件的部位保持当前模式。

```python
scheduled = RetargetMocapVariableScheduledToCharacter(
    host,
    spine_events=((1, "fk"), (5, "ik"), (8, "fk")),
    limb_events={
        ("arm", "R"): ((1, "fk"), (3, "ik"), (7, "fk")),
        ("arm", "L"): ((1, "fk"),),
        ("leg", "R"): ((1, "fk"), (6, "ik")),
        ("leg", "L"): ((1, "fk"),),
    },
)
root, groups, conversions = scheduled.apply_with_preset(
    source_root, preset, start_frame=1, end_frame=10,
)
```

事件入口允许五个模式通道已有原生动画曲线。默认要求写入区间的每个采样帧处于 FK 端点；区间内已有 IK 值会在写入前拒绝。显式传入 `replace_existing_modes=True` 后，区间内原模式可为 FK 或 IK 端点；入口先将这些采样帧写成 FK 基线，再写目标事件。已有混合权重等非端点值仍会拒绝。两种设置都会记录区间前后相邻帧的原值，只在缺少保护键时补键，并对区间模式键设置阶梯出切线。每个 IK 帧从完整 FK 动捕匹配对应控制值，最后复检全身采样姿态。四段角色的自生成来源及真实 FBX 输入均通过 10 帧模式、半帧切线、区间外原有 IK 键值与切线、区间内已有 IK 的显式覆盖、部分转换失败回滚、一次撤销重做和保存重开；最大矩阵误差约 `2.3e-4`。边界外任意子帧曲线形状、复杂动画层和未采样帧的身体姿态等价性仍待处理。

引擎骨名由 `BodyFbxNamingProfile` 指定。映射项左侧是 Body 关节短名，右侧是 FBX 中的发布名；没有列出的关节沿用 Body 短名。Root Motion 节点使用单独的 `root_name`。名称必须可移植且在整棵发布骨架中唯一；不存在的来源关节和命名冲突会在写文件前拒绝。

```python
from pathlib import Path
from adv_py.application import ExportBodyFbx
from adv_py.core import BodyFbxNamingProfile
```

`maya_body_fbx_export_smoke.py` 使用自生成 30 关节 Body 导出完整采样、单位转换、引擎骨名、无损简化及有界简化五份 FBX；重新在空 Maya 场景导入后得到 `EngineRoot|pelvis|spine_01`、一个 `head` 关节和 31 个总关节。MoCap 已能驱动上述 FK 控制器。

`BodyFbxExportProfile.curve_policy` 有 `sampled_linear`、`lossless_linear` 和 `bounded_linear` 三种值。默认 `sampled_linear` 保留 bake 的每个样本键；`lossless_linear` 只删除可由相邻保留键按直线精确恢复的内部键。`bounded_linear` 要求显式给出 `value_tolerance` 与 `matrix_tolerance`：前者限制每条通道在采样帧的数值误差，后者限制所有导出关节在验证时间点的世界矩阵元素误差。验证时间点包含全部烘焙帧、相邻烘焙帧的中点，以及首末帧外侧各半个采样步长。两个上限均须为正的有限数，不能用于其他策略。所有简化都保留首末键。

简化发生在发布时的临时 Maya 事务中，源场景的 bake 曲线、Undo 顶部、选择、当前帧和修改标志在导出后恢复；实际删键数与导出前快照计算的数量复核。有界策略在临时删键后重新采样全部导出关节，任一验证时间点的世界矩阵元素超过上限即拒绝发布，不生成 FBX。自生成 30 关节场景的 1–5 帧完整版、无损版和有界版 FBX 已在空场景重导入，并在烘焙帧、半帧和首末帧外各半帧复核；有界版最大世界矩阵元素误差约 `0.05`，低于设定上限 `0.2`。这些离散验证点不构成任意子帧的连续误差证明；动画层与更复杂来源仍未覆盖。

`euler_filter=True` 可与上述三种曲线策略组合，后台产品入口使用 `fbx-publish --euler-filter`，工作台在“发布”页勾选“整理旋转跨圈跳变”。导出器在临时发布事务中对每个导出关节的三条原生旋转动画曲线调用 Maya [Euler Filter](https://help.autodesk.com/cloudhelp/2022/CHS/Maya-Tech-Docs/CommandsPython/filterCurve.html)，随后复核全部烘焙帧的世界矩阵；若任一元素变化超过 `1e-5`，拒绝生成文件。与有界线性策略组合时，矩阵误差检查发生在删键和过滤之后。自生成肩部旋转 `170° → -170°` 的 FBX 在 1.5 帧重导入读回：原版约 `0°`，过滤版 `180°`；源场景旋转键值和 Undo 顶部在导出后恢复。该选项解决这类跨圈跳变，不改变未显式勾选时的默认曲线行为，也不提供任意连续时间姿态等价证明。
