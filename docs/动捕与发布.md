# 动捕与骨架发布

当前 MoCap 入口按显式的来源关节与 Body 关节映射建立临时约束，再把采样姿态烘焙到 Body。FBX 入口只导出已烘焙的独立导出骨架，导出前检查范围、来源依赖和目标文件占用。

映射预设由来源/目标关节短名、平移与旋转传递开关、预期 Body 关节数组成，不固化 Maya 命名空间。文件采用版本化 JSON 和内容摘要，保存时不覆盖同名文件；读取后仍需针对实际动捕源和 Body 执行 `InspectMocapBodyMapping`，由其检查根关节、拓扑与动画通道。`maya_mocap_mapping_smoke.py` 在 30 关节 Body 和 `TakeA` 命名空间动捕源上确认保存重读后的五项解析计划完全相同。

```python
from adv_py.application import InspectMocapBodyMapping, load_mocap_mapping_preset

preset = load_mocap_mapping_preset(r"D:\mocap\human.json")
plan = InspectMocapBodyMapping(host).execute(
    "|TakeA:Hips", preset.mappings,
    expected_body_joint_count=preset.expected_body_joint_count,
).require_valid()
```

引擎骨名由 `BodyFbxNamingProfile` 指定。映射项左侧是 Body 关节短名，右侧是 FBX 中的发布名；没有列出的关节沿用 Body 短名。Root Motion 节点使用单独的 `root_name`。名称必须可移植且在整棵发布骨架中唯一；不存在的来源关节和命名冲突会在写文件前拒绝。

```python
from pathlib import Path
from adv_py.application import ExportBodyFbx
from adv_py.core import BodyFbxNamingProfile

naming = BodyFbxNamingProfile(
    root_name="EngineRoot",
    joint_names=(("Root_M", "pelvis"), ("Spine1_M", "spine_01"), ("Head_M", "head")),
)
result = ExportBodyFbx(host).apply(
    Path(r"D:\publish\character.fbx"),
    start_frame=1,
    end_frame=5,
    naming_profile=naming,
)
```

`maya_body_fbx_export_smoke.py` 使用自生成 30 关节 Body 导出三份 FBX，其中第三份应用引擎骨名 Profile；重新在空 Maya 场景导入后得到 `EngineRoot|pelvis|spine_01`、一个 `head` 关节和 31 个总关节。现有 MoCap 流程尚未直接驱动角色控制 Rig；外部动画文件导入、映射预设和导出曲线策略仍需单独实现与验收。
