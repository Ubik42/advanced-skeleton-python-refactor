# 核心绑定的模块组合

当前角色构建以 `BuildBodyCharacterRig` 为组合入口。它消费已经生成的 Body 骨架，组合 Arm、Leg、可选 Hand、可选 Torso 与 Global；Fit 创建、Body 生成、蒙皮仍是独立用例。Torso 现已实现固定身体拓扑的分层 FK，以及四肢的根空间连接。

## 数据与执行边界

```text
Fit / Body / 场景连接
        │ 捕获一次
        ▼
BodyRebuildSafetyAudit（不可变的共同输入）
        ├── Arm.plan_from_safety()  → Arm plan
        ├── Leg.plan_from_safety()  → Leg plan
        └── Hand.plan_from_safety() → Hand plan（完整五指时）
                                      │
Character plan ◄───────────────────────┘
        │ 准备运行环境，复核输入
        ▼
一个角色事务
        ├── Arm.build_in_transaction()
        ├── Leg.build_in_transaction()
        ├── Hand.build_in_transaction()
        ├── Torso FK 与四肢空间连接（显式启用）
        ├── Global 创建与复检
        └── Body 绑定姿态 / Fit 输入复检
```

`BodyRebuildSafetyAudit` 保存 Body 关节快照、Fit 对称计划、设置与场景连接审计。名称沿用已有重建检查，但在此承担绑定前共同输入：各模块使用同一个对象，不再各自重复捕获完整 Body / Fit。模块仍会读取自己负责的名称占用与通道状态。

角色计划完成不等于场景被锁定。准备 Maya 插件等运行环境后，角色入口在事务开始时重新捕获共同输入；发现变化即停止，不创建模块节点。完整五指集合缺损会阻止角色构建，不会静默跳过 Hand。

## 模块接口

| 接口 | 职责 |
| --- | --- |
| `plan(...)` | 独立使用时捕获输入，转交共享输入计划入口 |
| `plan_from_safety(safety, ...)` | 从共同输入生成模块计划，并检查模块名称和专属通道 |
| `prepare_runtime()` | Arm / Leg 在事务前准备 twist 所需的 Maya 运行环境 |
| `build_in_transaction(plan)` | 在调用方已经建立的事务中创建模块，读回复检结果，不自行提交 |
| `apply(...)` | 独立使用入口，负责计划、运行环境、输入复核和事务 |

`build_in_transaction()` 是内部组合服务的公开接口，调用方承担事务与共同输入复核责任。通常从 `BuildBodyCharacterRig.apply()` 或模块自身的 `apply()` 进入；不把该接口作为任意场景下直接写入的快捷入口。模块通过计划中的 Body 完整路径捕获构建结果，不再额外接收可能与计划不一致的目标根参数。

Hand 在开始写入时仍复核手指通道。此前 Arm / Leg 已经创建了合法驱动，完整场景自然不再等于初始快照，因此此时检查 Hand 自己的输入与模块构建后条件，不重新执行角色初始状态审计。任一模块异常向外传播，由角色事务撤销已经创建的其他模块。

## 后续模块接入

Torso 通过相同的共同输入计划与事务内构建接口接入角色入口；它消费 Arm / Leg 已解析的机制链、FK offset 与 stretch 起点。后续空间切换与脊柱 IK 需要继续明确实际驱动语义，再由角色入口组合。目前保留显式、带类型的 Arm / Leg / Hand 计划和结果，尚无通用插件注册器或动态构建图。

开发批次以完整模块和角色工作流组织：先完成设计与实现，再集中执行回归与后台角色验证。场景预检、模块读回和事务回滚是运行时代码的一部分，不随开发测试频率降低而移除。

## 本轮集中验证

280 项纯 Python 回归通过，包括共同输入只捕获一次、准备运行环境后发生输入变化时阻止模块创建。Maya 2024 后台角色验证覆盖 70 关节角色的手腕 FK/IK 到手指控制空间传递，以及基础角色总控平移、旋转、1.5 倍缩放、四肢拉伸补偿和单次 Undo；两个脚本分别用时 5.282 秒、4.483 秒，均通过。此段记录前一轮组合架构整理的验证基线；新增 Torso 验证见下文。

## 躯干 FK 与四肢空间

`include_torso=True` 创建 7 个身体控制器：Root 骨盆、Spine1 腰、Chest 胸、Neck 颈、Head 头，以及左右 Scapula 肩胛。控制器沿身体父链嵌套；Root 开放平移和旋转，其余开放旋转，scale 锁定。控制器的 offset 层保存绑定姿态，动画通道初始为零。

每侧四肢有四处连接：FK 控制根接收对应肩胛或骨盆的完整位置 / 朝向；FK 与 IK 机制链根只接收该身体空间计算出的平移；stretch 测量起点同样跟随。机制根旋转仍由 FK 控制或 IK 求解负责，避免抢占输入。平移连接使用跳过旋转输出的 parent constraint，保留随父级旋转和缩放变化的局部偏移；普通 point constraint 的世界偏移不能表达这一关系。

手脚 IK 目标保留在 Global 空间中。骨盆移动时，机制起点随身体移动而目标不随骨盆移动。Global 的 TR 转为驱动 Torso 控制根，Body 根由骨盆控制器驱动；Global scale 另显式接入 Body 根三轴与已有四肢长度补偿，避免重复驱动同一 TR 通道。

以下代码在空 Maya 场景中创建可复现的五指角色，素材全部由代码生成：

```python
from maya import cmds
from adv_py.adapters import MayaBodyBuildHost
from adv_py.application import (
    CreateFitSkeleton, BuildSyntheticBodyWithHandSourceFit,
    BuildOrientedBodySkeleton, BuildBodyCharacterRig,
)

cmds.upAxis(axis="z", rotateView=False)
host = MayaBodyBuildHost()
container = CreateFitSkeleton(host).apply().state.path
BuildSyntheticBodyWithHandSourceFit(host).apply(container)
BuildOrientedBodySkeleton(host).apply(container)
rig = BuildBodyCharacterRig(host).apply(container, include_torso=True)
assert len(rig.body.joints) == 70
assert len(rig.torso.controls.controls) == 7
```

30 关节基础 Body 也支持该入口，此时没有 Hand 阶段。已有默认调用保持原行为，需要显式传入 `include_torso=True` 才会增加躯干控制。

本轮集中验收包含 284 项纯 Python 回归、70 / 30 关节 Maya Torso smoke 与旧角色总控 smoke。70 关节案例用时 5.902 秒、30 关节案例 5.026 秒，验证胸部到 FK 手臂、肩胛单侧隔离、颈头运动、骨盆平移、IK 目标保持与到达、stretch 起点跟随、1.5 倍全局缩放、绑定姿态恢复和整体 Undo / Redo。注入 Torso 读回失败后角色节点全部回滚；Maya 首次初始化的共享 IK solver 节点属于宿主运行环境，不作为角色产物统计。

当前不含脊柱 IK、躯干拉伸、头部瞄准、空间切换、任意数量脊椎映射或已有复杂角色适配。固定拓扑必须包含 Root / Spine1 / Chest / Neck / Head / 双侧 Scapula，并保持预期父链。
