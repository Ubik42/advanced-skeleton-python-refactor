# 角色动画操作

## 数据与入口

登记角色的用户控制通道可接原生 `animCurveTA / TL / TU` 曲线。登记恢复继续检查节点 UUID、父级、身体拓扑和内部连接，只对声明为用户可编辑的通道允许时间曲线。静态姿态接口仍拒绝动画输入。

| 入口 | 行为 |
| --- | --- |
| `CaptureAnimatedBodyCharacterPose(host).execute()` | 捕获当前帧完整控制值、空间状态及身体参考 |
| `KeyBodyCharacterPose(host).plan(pose)` / `.apply(pose)` | 只读预演；当前帧写入全部 157 / 261 个通道，其他帧键值保留 |
| `CaptureBodyCharacterAnimation(host).execute(start, end, step=1)` | 显式范围采样，恢复当前时间和文件修改状态 |
| `ApplyBodyCharacterAnimation(host).plan(clip)` / `.apply(clip)` | 批量写入采样帧，在单一事务内读回控制、空间和身体矩阵 |
| `BakeBodyCharacterSpineMode(host).execute(start, end, "ik" / "fk", step=1)` | 对已有动画逐帧匹配脊柱模式，写入匹配后的完整角色通道 |

`CharacterAnimation` 包含场景时间单位和严格递增的 `(frame, CharacterPose)` 序列。每个姿态保存语义通道值、五组空间来源、空间目标矩阵和身体世界矩阵；身体矩阵用于验证求解结果，不直接写到骨骼。文档不含场景路径，使用版本和 SHA-256 摘要。所有采样必须属于相同绑定布局和空间来源。

范围入口接受整数起止帧和正整数步长，结束帧必须落在步长上，最多 2000 个采样。文件上限 64 MB。`save_character_animation` 在目标目录中写临时文件、复检并原子创建新文件，拒绝覆盖和并发抢占；`load_character_animation` 严格检查字段、摘要、数值与时间顺序。

## 已保存角色用例

Maya 已初始化，场景已包含标准完整角色登记；源目录已加入 Python 搜索路径：

```python
from adv_py.adapters import MayaBodyBuildHost
from adv_py.application import (
    CaptureBodyCharacterAnimation, ApplyBodyCharacterAnimation,
    BakeBodyCharacterSpineMode, save_character_animation, load_character_animation,
)

host = MayaBodyBuildHost()
clip = CaptureBodyCharacterAnimation(host).execute(1, 21, step=1)
save_character_animation(clip, r"D:\animation-output\walk.json")

# 修改曲线后恢复；目标文件父目录需提前存在。
ApplyBodyCharacterAnimation(host).apply(load_character_animation(r"D:\animation-output\walk.json"))

# 将这段脊柱运动转成 IK 控制，保留采样帧的全身姿态。
BakeBodyCharacterSpineMode(host).execute(1, 21, "ik")
```

`examples/maya_saved_character_animation.py` 提供同一流程的文件封装。每次写入或转换各占一笔 Undo；任何帧读回失败会恢复整笔操作。采样恢复调用前的时间，不向 Undo 队列写入切帧命令。

## 脊柱动画求解

匹配时临时断开用户曲线，将该帧的数值交给既有静态匹配器，再恢复原曲线连接；采样全部通过后才写键。临时操作、求解器安装和最终写键同属一笔事务。原曲线节点和采样范围外的键值保留。

Maya 默认共享 RP 求解器在接近伸直的弯曲姿态下，其 `1e-5` 求解容差可能使腰部世界位置误差超过 `1e-4`。动画转换给本角色脊柱安装独立 `AdvPy_SpineRPSolver`，容差为 `1e-10`；通过归属标记、角色根消息连接和唯一输出审计。Maya 共享求解器保持原设置，Undo 同时撤销独立求解器安装。已有 IK 姿态在升级前采样，转换后仍与升级前结果比较。

## 已验证范围与限制

单帧写键和片段恢复覆盖 30 / 70 关节标准角色、157 / 261 通道、348 / 828 顶点代理网格。片段恢复覆盖文件往返、其他帧键值保留、一次 Undo / Redo、部分写入失败回滚、帧率不匹配拒绝，以及独立进程重开后继续编辑。当前进程片段恢复的网格误差为 0；重开最大位置分量误差约 `2.98e-8 cm`。

脊柱动画双向转换在 30 / 70 关节通过，70 关节最大身体矩阵元素误差约 `1.81e-6`，最大网格位置分量误差约 `1.91e-6 cm`。独立求解器安装、曲线与连接支持一次 Undo / Redo；注入匹配异常后完整恢复。70 关节转换场景在新进程重开后通过登记复检、蒙皮比较和再次模式转换。全量纯 Python 回归为 305 项。

写入点使用线性 Euler 切线；保留的是其他帧已有键的时间和值，不承诺相邻区间曲线形状、原切线或任意子帧姿态不变。模式转换的匹配保证同样只覆盖显式采样帧。单帧可令 `start == end`；整段动画通常使用逐帧采样。

当前要求 cm / degree、相同时间单位、无动画层、无 namespace 的非引用单角色、未锁定通道和独占曲线输出。拒绝共享曲线、外部输入和不匹配的空间来源。脊柱使用固定双段和正等比缩放，源模式必须位于 FK / IK 端点。片段写入不改变空间绑定；可动画化的空间来源、完整角色多 namespace 和保留数据的重建仍在[剩余开发清单](剩余开发清单.md)中。
