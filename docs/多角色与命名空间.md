# 多角色与命名空间

## 显式选择角色

`MayaBodyBuildHost(namespace="hero")` 将构建、登记、姿态、动画和空间操作限定到 `hero` 命名空间。命名空间需已存在；构造适配器只检查身份，不创建场景对象。`namespace="shot:hero"` 表示嵌套命名空间，`namespace=""` 明确选择根命名空间。省略参数保留原单角色接口，多角色场景应显式指定身份。

```python
from maya import cmds
from adv_py.adapters import MayaBodyBuildHost
from adv_py.application import SwitchBodyCharacterSpace, BakeBodyCharacterLimbMode

# 发现已有角色：包含实际登记节点路径、UUID 和引用标志。
characters = MayaBodyBuildHost.discover_scene_characters()
hero = MayaBodyBuildHost(namespace="hero")
partner = MayaBodyBuildHost(namespace="partner")

SwitchBodyCharacterSpace(hero).execute("hand_R", "body", 11)
BakeBodyCharacterLimbMode(partner).execute(1, 21, "arm", "L", "ik")

# 与原生 Maya 工具交互时取得实际场景地址。
registration = hero.read_character_registration()
cmds.select(hero.scene_address(registration.body_root))
```

登记读取始终使用所选适配器，不从当前选择或“找到的第一个角色”推断目标。每个角色保存自己的登记节点和成员 UUID，角色内部的默认名称不需要改名。

## 内部地址与场景地址

核心计划、登记文档和角色操作使用角色内部地址；命名空间只在 Maya 命令边界映射。以 `hero` 为例：

| 内部地址 | 实际场景地址 |
| --- | --- |
| `AdvPy_CharacterRegistry` | `hero:AdvPy_CharacterRegistry` |
| `\|Root_M` | `\|hero:Root_M` |
| `\|Root_M\|Hip_R.rotateX` | `\|hero:Root_M\|hero:Hip_R.rotateX` |
| `AdvPy_CharacterProxy.vtx[4:8]` | `hero:AdvPy_CharacterProxy.vtx[4:8]` |

`scene_address()` 用于向原生 Maya 命令、选择和外部工具传递路径。内部结果不能直接交给原生 `cmds` 并依赖当前命名空间猜测。

命令边界只转换已声明的节点参数、连接端口和节点返回值；属性值、JSON、文件名、节点类型、关键帧切线及显示文本不做字符串替换。角色成员的全场查询先限定到本命名空间，再读取 UUID，避免事务结束时为另一个角色记录变换。

外部连接保留其实际命名空间；根命名空间中的外部节点用显式根地址表示，避免与角色内部的同名节点混淆。节点写操作拒绝其他角色的地址。动画登记还检查原生曲线属于当前角色，不能通过接入另一角色的单独曲线绕过归属检查。

## 创建两个角色

`examples/maya_complete_character.py` 的示例入口接受带命名空间的 `CharacterExampleHost`。以下代码在 Z-up、degree、Undo 开启的场景中创建一个 30 关节角色和一个包含手指的 70 关节角色，并登记：

```python
from maya import cmds
from maya_complete_character import CharacterExampleHost, build_character
from adv_py.application import RegisterBodyCharacter

for namespace, with_hand in (("hero", False), ("partner", True)):
    cmds.namespace(addNamespace=namespace)
    host = CharacterExampleHost(namespace=namespace)
    character = build_character(with_hand=with_hand, host=host)
    RegisterBodyCharacter(host).apply(character.rig)
```

`examples` 和 `src` 目录需位于 Python 搜索路径。示例为每个角色生成独立身体、控制器、代理网格和显式蒙皮，命名空间创建与角色构建是两个操作。完整构建仍占一笔 Undo；构建撤销后保留空命名空间。

## Maya 状态与引用边界

Maya 的部分节点创建命令会在重做时重新读取当前命名空间。适配器将进入及恢复命名空间的命令与节点创建保存在同一事务中，确保 Undo / Redo 重建到原角色。调用结束恢复此前的命名空间和选择，包括选择位于角色外的节点。Maya `relativeNames` 必须关闭。

默认 IK 求解器明确创建在场景根命名空间，角色可以共享其默认行为；脊柱高精度求解器仍在角色自己的命名空间中创建、登记和审计，不改变另一个角色的求解器设置。

引用角色可被发现，记录中 `referenced=True`。当前角色登记及写入流程拒绝引用节点，不创建 reference edit，也不自动导入引用。发现后可以由产品入口显示只读状态；本批没有提供引用角色的可写编辑流程。

## 已验证范围

后台入口为 `validation/maya_character_namespace_smoke.py`：

- 同场 30 / 70 关节角色分别完整构建、显式蒙皮及登记；启用四肢与空间动画后分别为 312 / 416 通道。
- 两个角色的完整构建 Undo / Redo 保持各自网格位置；登记路径和 UUID 独立。
- 对一方进行全身写键、空间事件、片段恢复、四肢及脊柱 FK/IK 转换时，另一方的姿态、蒙皮和曲线保持一致。
- 动画操作 Undo / Redo 保持隔离；恢复角色外选择和当前命名空间。
- 动画场景在另一进程再次重开，两角色姿态与实际网格通过比较；继续编辑 70 关节角色不改变 30 关节角色。
- 注入全身写键异常后，目标曲线与姿态整体回滚，另一角色保持不变；跨角色原生动画曲线输入在登记检查时拒绝。
- 场景作为引用载入后，发现 `shot:hero`、`shot:partner`；写入边界拒绝引用，文件修改状态保持不变。
- 单元回归覆盖嵌套命名空间、节点/端口/组件地址、外部根节点识别、属性数据不改写与跨角色写入拒绝。
