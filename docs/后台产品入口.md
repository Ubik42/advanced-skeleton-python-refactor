# 后台产品入口

## Maya 内角色工作台

安装并使 `adv_py` 位于 Maya 的 Python 路径后，可在 Maya 的 Python 命令区打开角色工作台：

```python
from adv_py.product.maya_panel import show_panel
show_panel()
```

面板按场景命名空间选择角色，提供 Fit 文档导入／导出、完整 Body 构建与登记、显式网格绑定、完整权重文档导入／导出、姿态和全身动画片段的捕获／应用。构建在一个 Maya 撤销事务内完成；面板不会自动保存当前场景。操作区展示进度与错误，数据写入只调用 `adv_py.application` 用例。当前面板还未纳入 Face、动捕、FBX 发布和预设目录管理，这些仍需补齐。

`validation/product_maya_panel_offscreen.py` 在无可见窗口的 Qt 环境中检查六页中文工作区、角色选择、动作分发、状态反馈与排版，包括面部资产长页面底部；`validation/maya_panel_controller_smoke.py` 在后台 Maya 自生成场景中检查 Fit 导出、完整角色构建、角色发现、姿态和动画文档往返、预设兼容性、面部目标资产往返、资产版本登记／合并／导出、控制构建、面部动画及真实 FBX 发布。`validation/maya_panel_mocap_controller_smoke.py` 用自生成外部 FBX 与映射预设检查导入、独立命名空间和角色控制曲线写入。离屏截图用于排版检查，不代表已完成真实 Maya 可见窗口的人工操作验收。

工作台的“保留数据重建”使用尚未占用的暂存命名空间；用户附件根逐行填写。面部控制若挂在旧 Head 关节下，也须作为附件根填写。重建经归属审计、数据转移及原位替换后一次提交；未声明的旧 Rig 子节点会拒绝重建。后台控制层已用包含面部控制的自生成角色验收。

重建、动捕导入与 FBX 发布会在状态区显示当前处理阶段。工作台动捕写入失败时，只在撤销栈顶仍是本次 FBX 导入时撤销该导入，并检查来源命名空间已移除；撤销栈若被其他操作改变则拒绝误撤销。后台验收用关节数不匹配的有效预设触发失败，确认来源清理、既有撤销历史与原角色保持。

`adv-rig` 是 Maya 2024 standalone 的命令行入口。每次命令在独立进程中打开一个现有 `.ma` 或 `.mb` 场景；写入命令只生成新的 `.ma` 文件，不覆盖输入或已有输出。场景修改由 application 用例完成，入口负责文件读写、角色选择及进度／错误报告。根命名空间使用 `--namespace :`，其他角色使用 `characters` 返回的命名空间。

```powershell
$env:PYTHONPATH = 'src'
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  characters validation\results\maya2024-face-performance.ma
```

自生成双目标测试场景中的一条角色记录形如：

```json
{
  "namespace": "hero",
  "name": "AdvPy_CharacterRegistry",
  "writable": true,
  "joint_count": 72,
  "channel_count": 274,
  "face_control": "|Root_M|Spine1_M|Spine2_M|Spine3_M|Chest_M|Neck_M|Head_M|AdvPy_FaceControls"
}
```

`fit-export` 把现有 Fit 容器的关节、朝向、标签和设置写为可移植文档；`fit-import` 在匹配向上轴的场景中新建容器并读入该文档。两者均拒绝覆盖已有输出。随后可用 `body-build` 在一个 Maya 撤销事务中构建 Body 骨架、完整控制 Rig 和角色登记，并另存新场景。默认使用标准双段脊柱；可变脊柱场景须传入与 Fit 一致的 `--spine-segments`。`--head-aim` 显式加入头部瞄准控制。构建失败会回滚这三个阶段，不写输出场景，输入文件保持原样。这里不自动蒙皮或生成生产网格。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  fit-export fit-only.ma --namespace : --output character.fit.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  fit-import empty-z-up.ma --namespace : --document character.fit.json `
  --output imported-fit.ma
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  body-build imported-fit.ma --namespace : --output registered-body.ma
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  body-build variable-fit.ma --namespace hero --spine-segments 4 `
  --head-aim --output variable-registered.ma
```

独立进程验收用自生成 Fit 场景构建并重开了标准 30 关节／157 控制通道角色，以及 `hero` 命名空间的 4 段脊柱、带头部瞄准的 72 关节／281 通道角色。还会检查 Fit 文档导出→空场景导入→角色构建→重开、源角色姿态与动画片段应用到导入后角色，以及缺失 Fit 时不写输出场景。完整构建可一次撤销／重做；登记阶段故障注入会回滚已创建骨架和控制。Fit 往返后绑定矩阵最大差异为 `8.9e-16`；角色兼容摘要按小数点后八位规范化矩阵和骨长，消除此级别浮点噪声，实际绑定数值仍以 `1e-5` 上限逐项验收。旧版精确摘要的姿态文档在原场景仍可读取，并在应用时升级为可移植摘要；验证入口为 `validation/product_body_build_smoke.py`。

`face-build` 将已有中性网格和表情／口型目标装配为 Head 控制与 BlendShape。输入文档显式给出目标类别和网格路径；预检拓扑、顶点差异及名称，写入后复检属性、连接和真实网格位移。

```json
{
  "neutral": "|FaceNeutral",
  "targets": [
    {"name": "smile_R", "kind": "expression", "mesh": "|SmileTarget"},
    {"name": "viseme_A", "kind": "viseme", "mesh": "|VisemeATarget"}
  ]
}
```

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-build unbuilt.ma --namespace hero --spec face-build.json `
  --output face-built.ma
```

`face-target` 接收明确的中性网格、目标路径、语义类别及顶点标记文档。下面的标记将第 3 个顶点沿对象空间 Y/Z 轴移动 `0.2/0.1`，半径 `1.0` 内的其他顶点受平滑衰减影响：

```json
{"landmarks":[{"vertex":3,"displacement":[0.0,0.2,0.1],"radius":1.0}]}
```

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-target input.ma --namespace hero --neutral '|FaceNeutral' `
  --name blink_L --kind expression --target '|BlinkTarget' `
  --landmarks blink-landmarks.json --output with-blink.ma
```

`face-asset-export` 将现有雕刻目标的非零顶点位移写成版本化 JSON；`face-asset-import` 在匹配的中性网格上重新创建目标。输出资产文档和场景均不覆盖已有文件。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-export source.ma --namespace hero --neutral '|FaceNeutral' `
  --name smile_R --kind expression --target '|SmileTarget' --frame 1 `
  --output smile.asset.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-import other-character.ma --namespace hero --neutral '|FaceNeutral' `
  --asset smile.asset.json --target '|ImportedSmile' --output imported.ma
```

资产版本目录的三个命令不需要启动 Maya。目录写入使用内容摘要寻址和不可覆盖的版本引用；列目录会报告损坏项，导出时重新验证文件内容。

```powershell
$env:PYTHONPATH = 'src'
python -m adv_py.product face-library-add --library face-library `
  --asset smile.asset.json --release 1.0.0
python -m adv_py.product face-library-list --library face-library
python -m adv_py.product face-library-export --library face-library `
  --name smile_R --release 1.0.0 --output selected-smile.asset.json
```

`face-animation` 接收 `face_performance_to_json` 生成的带摘要动画文档。`--control` 取 `characters` 返回的逻辑路径；文档时间单位必须与场景相同，通道须属于面部清单。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-animation with-blink.ma --namespace hero `
  --control '|Root_M|Spine1_M|Spine2_M|Spine3_M|Chest_M|Neck_M|Head_M|AdvPy_FaceControls' `
  --clip mouth.json --output animated.ma
```

成功结果以 JSON 写到标准输出；场景打开、资产生成、动画应用和保存进度以 JSON 事件写到标准错误输出。预检或写入失败返回退出码 `2` 与错误事件，不生成输出场景。`characters` 会列出发现但不可写的登记及原因；引用角色仍按 application 合同拒绝修改。

全身姿态与动画使用已有的路径无关文档合同。`pose-capture` 从当前帧或显式 `--frame` 捕获控制值、空间状态和 Body 参考；`pose-apply` 检查角色兼容摘要，恢复控制、空间和实际身体姿态。静态姿态不能写到已有动画输入的控制通道。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  pose-capture input.ma --namespace : --frame 1 --output current.pose.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  pose-apply input.ma --namespace : --pose target.pose.json --output posed.ma
```

`animation-capture` 按整数帧范围采样完整角色，`animation-apply` 在一个可撤销事务中写回文档；时间单位、通道、角色兼容性、片段外旧键和结果姿态由 application 层校验。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  animation-capture animated.ma --namespace : --start 1 --end 21 --step 5 `
  --output captured.animation.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  animation-apply animated.ma --namespace : --clip captured.animation.json `
  --output restored.ma
```

`presets` 扫描目录下最多 256 个 JSON 文件，分别报告格式、与当前角色的布局兼容性及当前场景是否可写。未识别文件和损坏文档会带原因列出，不阻断其他预设的检查。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  presets input.ma --namespace : --directory presets
```

`skin-bind` 将场景内现有网格绑定到逐项指定的关节，写出新场景；它不创建网格，也不自动猜测影响关节。`skin-export` 将一个 skinCluster 的全部顶点权重导出为带内容摘要的 JSON 文档。`--skin` 是 skinCluster 名称，`--mesh` 与 `--influence` 使用完整 DAG 路径。`skin-import` 先核对顶点数、影响关节集合、最大影响数设置与目标 Skin，再一次性写入并保存新场景。跨角色或网格路径不同时，`--mapping` 明确给出目标 Skin、目标网格和每个源／目标关节对应；默认必须覆盖全部源影响关节。`--allow-unweighted-missing` 只允许省略没有非零权重的源关节。源 Skin 若关闭 `maintainMaxInfluences`，新绑定时用 `--no-maintain-max-influences` 保持同一设置；该开关与文档不一致时导入会拒绝。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  skin-export input.ma --namespace : --skin SkinCluster --mesh '|SkinMesh' `
  --output weights.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  skin-import changed.ma --namespace : --weights weights.json `
  --output restored.ma
```

跨角色恢复的映射文档示例：

```json
{
  "target_skin": "TargetSkin",
  "target_mesh": "|TargetMesh",
  "influences": [
    {"source": "|SkinRoot", "target": "|TargetRoot"},
    {"source": "|SkinRoot|SkinTip", "target": "|TargetRoot|TargetTip"}
  ]
}
```

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  skin-bind target.ma --namespace : --mesh '|TargetMesh' `
  --influence '|TargetRoot' --influence '|TargetRoot|TargetTip' `
  --skin TargetSkin --max-influences 2 --no-maintain-max-influences `
  --output target-bound.ma
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  skin-import target-bound.ma --namespace : --weights weights.json `
  --mapping target.mapping.json --output target-restored.ma
```

自生成 24 顶点网格的独立进程验收会导出源权重、在另一组关节上新建 Skin、按显式映射导入，并在新进程重开后逐顶点复核完整权重文档；遗漏承载权重的关节会拒绝生成场景。验证入口为 `validation/product_skin_entry_smoke.py`。

`fbx-publish` 从带 Python 所有权标记的标准 Body 场景构建临时 Root Motion 和导出骨架，按整数帧烘焙后发布二进制 FBX。输出只含独立的 Root Motion 和骨架；源 `.ma` 文件不写回。`--namespace :` 对应根命名空间，其他命名空间填写角色前缀。`--curve-policy lossless_linear` 会删除可由相邻线性键精确恢复的内部键；默认 `sampled_linear` 保留每个采样键。`bounded_linear` 需要同时指定正的 `--value-tolerance` 和 `--matrix-tolerance`，分别限制通道采样值及全部导出关节采样帧的世界矩阵元素误差；超限拒绝生成 FBX。输出目录须已存在，目标 FBX 不可覆盖。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  fbx-publish animated.ma --namespace : --start 1 --end 21 --step 1 `
  --curve-policy lossless_linear --output published.fbx
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  fbx-publish animated.ma --namespace : --start 1 --end 21 --step 1 `
  --curve-policy bounded_linear --value-tolerance 0.2 `
  --matrix-tolerance 0.2 --output compressed.fbx
```

`mocap-retarget` 读取外部 FBX、带摘要的关节映射预设以及已登记角色场景。FBX 先在独立 Maya 进程解析，再作为专属 `--source-namespace` 骨架导入场景；该名称必须尚未占用。`--namespace` 指定目标角色，`--mode` 可选 `fk`、`limb-ik` 或 `full-ik`。四肢 IK 模式要求目标角色已有完整四肢动画通道；全身 IK 还要求标准双段脊柱合同。来源关节层级、目标角色、帧范围和控制可写性由映射及动画用例预检。命令只写新的 `.ma`，保留原场景和来源 FBX。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  mocap-retarget character.ma --namespace : --source take.fbx `
  --mapping take.mapping.json --source-namespace ExternalTake `
  --start 1 --end 10 --mode full-ik --output retargeted.ma
```

`rebuild` 通过原有的保留数据重建用例执行同布局角色替换。`--replacement` 是尚未占用的暂存命名空间；`--extension` 可重复指定需要保留的用户附件根。根命名空间角色使用 `--namespace :`，命名空间内角色填实际名称。不同拓扑或绑定布局仍按重建合同拒绝。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  rebuild animated.ma --namespace : --replacement ProductRebuildStage `
  --output rebuilt.ma
```

独立进程验收从一份已登记但未构建面部的 72 关节测试场景出发，先生成第三个目标，再将三个目标接到面部控制与 BlendShape，最后写入口型片段；同时检查输出文件防覆盖、时间单位错误拒绝，以及新进程重开后的目标来源、角色登记和关键帧读回。验收命令见 `validation/product_entry_smoke.py`；未构建场景由前一条 Face 宿主验证命令生成。

外部目标资产的独立进程验收将雕刻目标导出、登记并解析 `1.0.0` 版本、在新场景中导入、再构建 BlendShape；重开的目标网格与原雕刻网格最大顶点误差小于 `1e-6`。同版本不同内容、基准位置不匹配的导入均被拒绝。命令见 `validation/product_face_asset_smoke.py`。

`face-library-merge` 接收同一通道的共同基线与两个分支版本，将不冲突的顶点改动登记为新版本；冲突会列出顶点索引且不创建目标版本。合并引用保留三个来源版本及对象摘要，来源内容在之后损坏时可检测。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-library-merge --library face-library --name smile_R `
  --base 1.0.0 --left 1.1.0 --right 1.2.0 --release 2.0.0
```

合并后的 `2.0.0` 已在独立进程导出并导回自生成 Maya 场景，重开后网格逐顶点位置与合并资产一致，验收命令同为 `validation/product_face_asset_smoke.py`。

`face-asset-transfer` 将雕刻位移转移到不同拓扑。源中性网格可用同场景的 `--source-neutral` 指定，或先在源场景执行 `face-geometry-export`，再在目标场景用 `--source-geometry` 读取带摘要的顶点与三角面文档。两种来源只能选一项。默认要求源、目标网格的对象空间坐标已对齐；有刚体位置或朝向差异时传入 `--alignment`，文件包含三个源／目标顶点对应 `pairs` 和 `max_residual`。`--max-distance` 是每个目标顶点离源表面的最大容许距离。跨场景文档保存向上轴及长度单位，目标场景不匹配时拒绝。命令只写新资产，不改动场景；转移资产仍需用 `face-asset-import` 导入到目标中性网格。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-transfer two-topologies.ma --namespace hero `
  --source-neutral '|FaceNeutral' --target-neutral '|FaceNeutralDense' `
  --asset smile.asset.json --max-distance 0.001 `
  --output smile.dense.asset.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-geometry-export source.ma --namespace hero --neutral '|FaceNeutral' `
  --output face-source.geometry.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-transfer target.ma --namespace hero `
  --source-geometry face-source.geometry.json `
  --target-neutral '|FaceNeutralDense' --asset smile.asset.json `
  --max-distance 0.001 --output smile.cross-scene.asset.json
```

独立进程验收以 4 顶点源网格和 9 顶点目标网格运行转移、导入、重开及 BlendShape 构建；另存的目标场景已删除源中性网格，使用源几何文档仍得到相同结果。目标顶点最大位置误差 `5.96e-8`，控制驱动最大位移 `0.5`。5 顶点目标网格旋转、平移后通过三点对齐完成转移与导入，最大位置误差 `2.38e-7`。远离源表面的目标、摘要被改动的几何文档以及源／目标长度单位不一致的文档被拒绝，不生成资产。命令见 `validation/product_face_transfer_smoke.py`。
