# 后台产品入口

`adv-rig` 是 Maya 2024 standalone 的命令行入口。每次命令在独立进程中打开一个现有 `.ma` 或 `.mb` 场景；写入命令只生成新的 `.ma` 文件，不覆盖输入或已有输出。场景修改由 application 用例完成，入口负责文件读写、角色选择及进度／错误报告。根命名空间使用 `--namespace :`，其他角色使用 `characters` 返回的命名空间。

```powershell
$env:PYTHONPATH = 'src'
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  characters validation\results\maya2024-face-performance.ma
```

自生成双目标测试场景中的一条角色记录形如：

```json
{
  "namespace": "hero",
  "name": "AdvPy_CharacterRegistry",
  "writable": true,
  "joint_count": 72,
  "channel_count": 274,
  "face_control": "|Root_M|Spine1_M|Spine2_M|Spine3_M|Chest_M|Neck_M|Head_M|AdvPy_FaceControls"
}
```

`face-build` 将已有中性网格和表情／口型目标装配为 Head 控制与 BlendShape。输入文档显式给出目标类别和网格路径；预检拓扑、顶点差异及名称，写入后复检属性、连接和真实网格位移。

```json
{
  "neutral": "|FaceNeutral",
  "targets": [
    {"name": "smile_R", "kind": "expression", "mesh": "|SmileTarget"},
    {"name": "viseme_A", "kind": "viseme", "mesh": "|VisemeATarget"}
  ]
}
```

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-build unbuilt.ma --namespace hero --spec face-build.json `
  --output face-built.ma
```

`face-target` 接收明确的中性网格、目标路径、语义类别及顶点标记文档。下面的标记将第 3 个顶点沿对象空间 Y/Z 轴移动 `0.2/0.1`，半径 `1.0` 内的其他顶点受平滑衰减影响：

```json
{"landmarks":[{"vertex":3,"displacement":[0.0,0.2,0.1],"radius":1.0}]}
```

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-target input.ma --namespace hero --neutral '|FaceNeutral' `
  --name blink_L --kind expression --target '|BlinkTarget' `
  --landmarks blink-landmarks.json --output with-blink.ma
```

`face-asset-export` 将现有雕刻目标的非零顶点位移写成版本化 JSON；`face-asset-import` 在匹配的中性网格上重新创建目标。输出资产文档和场景均不覆盖已有文件。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-export source.ma --namespace hero --neutral '|FaceNeutral' `
  --name smile_R --kind expression --target '|SmileTarget' --frame 1 `
  --output smile.asset.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-import other-character.ma --namespace hero --neutral '|FaceNeutral' `
  --asset smile.asset.json --target '|ImportedSmile' --output imported.ma
```

资产版本目录的三个命令不需要启动 Maya。目录写入使用内容摘要寻址和不可覆盖的版本引用；列目录会报告损坏项，导出时重新验证文件内容。

```powershell
$env:PYTHONPATH = 'src'
python -m adv_py.product face-library-add --library face-library `
  --asset smile.asset.json --release 1.0.0
python -m adv_py.product face-library-list --library face-library
python -m adv_py.product face-library-export --library face-library `
  --name smile_R --release 1.0.0 --output selected-smile.asset.json
```

`face-animation` 接收 `face_performance_to_json` 生成的带摘要动画文档。`--control` 取 `characters` 返回的逻辑路径；文档时间单位必须与场景相同，通道须属于面部清单。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-animation with-blink.ma --namespace hero `
  --control '|Root_M|Spine1_M|Spine2_M|Spine3_M|Chest_M|Neck_M|Head_M|AdvPy_FaceControls' `
  --clip mouth.json --output animated.ma
```

成功结果以 JSON 写到标准输出；场景打开、资产生成、动画应用和保存进度以 JSON 事件写到标准错误输出。预检或写入失败返回退出码 `2` 与错误事件，不生成输出场景。`characters` 会列出发现但不可写的登记及原因；引用角色仍按 application 合同拒绝修改。

全身姿态与动画使用已有的路径无关文档合同。`pose-capture` 从当前帧或显式 `--frame` 捕获控制值、空间状态和 Body 参考；`pose-apply` 检查角色兼容摘要，恢复控制、空间和实际身体姿态。静态姿态不能写到已有动画输入的控制通道。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  pose-capture input.ma --namespace : --frame 1 --output current.pose.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  pose-apply input.ma --namespace : --pose target.pose.json --output posed.ma
```

`animation-capture` 按整数帧范围采样完整角色，`animation-apply` 在一个可撤销事务中写回文档；时间单位、通道、角色兼容性、片段外旧键和结果姿态由 application 层校验。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  animation-capture animated.ma --namespace : --start 1 --end 21 --step 5 `
  --output captured.animation.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  animation-apply animated.ma --namespace : --clip captured.animation.json `
  --output restored.ma
```

`presets` 扫描目录下最多 256 个 JSON 文件，分别报告格式、与当前角色的布局兼容性及当前场景是否可写。未识别文件和损坏文档会带原因列出，不阻断其他预设的检查。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  presets input.ma --namespace : --directory presets
```

`skin-export` 将一个 skinCluster 绑定网格的全部顶点权重导出为带内容摘要的 JSON 文档。`--skin` 是 skinCluster 名称，`--mesh` 使用场景中的完整 DAG 路径。`skin-import` 从文档读取原 skinCluster 和网格路径，先核对顶点数、影响关节及目标场景，再一次性写入并保存新场景；路径或绑定布局不一致会拒绝。跨角色路径映射仍由 application 用例提供，当前命令不暴露映射参数。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  skin-export input.ma --namespace : --skin SkinCluster --mesh '|SkinMesh' `
  --output weights.json
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  skin-import changed.ma --namespace : --weights weights.json `
  --output restored.ma
```

`fbx-publish` 从带 Python 所有权标记的标准 Body 场景构建临时 Root Motion 和导出骨架，按整数帧烘焙后发布二进制 FBX。输出只含独立的 Root Motion 和骨架；源 `.ma` 文件不写回。`--namespace :` 对应根命名空间，其他命名空间填写角色前缀。`--curve-policy lossless_linear` 会删除可由相邻线性键精确恢复的内部键；默认 `sampled_linear` 保留每个采样键。输出目录须已存在，目标 FBX 不可覆盖。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  fbx-publish animated.ma --namespace : --start 1 --end 21 --step 1 `
  --curve-policy lossless_linear --output published.fbx
```

`mocap-retarget` 读取外部 FBX、带摘要的关节映射预设以及已登记角色场景。FBX 先在独立 Maya 进程解析，再作为专属 `--source-namespace` 骨架导入场景；该名称必须尚未占用。`--namespace` 指定目标角色，`--mode` 可选 `fk`、`limb-ik` 或 `full-ik`。四肢 IK 模式要求目标角色已有完整四肢动画通道；全身 IK 还要求标准双段脊柱合同。来源关节层级、目标角色、帧范围和控制可写性由映射及动画用例预检。命令只写新的 `.ma`，保留原场景和来源 FBX。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  mocap-retarget character.ma --namespace : --source take.fbx `
  --mapping take.mapping.json --source-namespace ExternalTake `
  --start 1 --end 10 --mode full-ik --output retargeted.ma
```

`rebuild` 通过原有的保留数据重建用例执行同布局角色替换。`--replacement` 是尚未占用的暂存命名空间；`--extension` 可重复指定需要保留的用户附件根。根命名空间角色使用 `--namespace :`，命名空间内角色填实际名称。不同拓扑或绑定布局仍按重建合同拒绝。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  rebuild animated.ma --namespace : --replacement ProductRebuildStage `
  --output rebuilt.ma
```

独立进程验收从一份已登记但未构建面部的 72 关节测试场景出发，先生成第三个目标，再将三个目标接到面部控制与 BlendShape，最后写入口型片段；同时检查输出文件防覆盖、时间单位错误拒绝，以及新进程重开后的目标来源、角色登记和关键帧读回。验收命令见 `validation/product_entry_smoke.py`；未构建场景由前一条 Face 宿主验证命令生成。

外部目标资产的独立进程验收将雕刻目标导出、登记并解析 `1.0.0` 版本、在新场景中导入、再构建 BlendShape；重开的目标网格与原雕刻网格最大顶点误差小于 `1e-6`。同版本不同内容、基准位置不匹配的导入均被拒绝。命令见 `validation/product_face_asset_smoke.py`。

`face-library-merge` 接收同一通道的共同基线与两个分支版本，将不冲突的顶点改动登记为新版本；冲突会列出顶点索引且不创建目标版本。合并引用保留三个来源版本及对象摘要，来源内容在之后损坏时可检测。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-library-merge --library face-library --name smile_R `
  --base 1.0.0 --left 1.1.0 --right 1.2.0 --release 2.0.0
```

合并后的 `2.0.0` 已在独立进程导出并导回自生成 Maya 场景，重开后网格逐顶点位置与合并资产一致，验收命令同为 `validation/product_face_asset_smoke.py`。

`face-asset-transfer` 用同一场景中的源、目标中性网格将雕刻位移转移到不同拓扑。两张网格须位于指定角色命名空间并在对象空间对齐；`--max-distance` 是每个目标顶点离源表面的最大容许距离。命令只写新资产，不改动场景；转移资产仍需用 `face-asset-import` 导入到目标中性网格。

```powershell
& 'C:\Program Files\Autodesk\Maya2024\bin\mayapy.exe' -m adv_py.product `
  face-asset-transfer two-topologies.ma --namespace hero `
  --source-neutral '|FaceNeutral' --target-neutral '|FaceNeutralDense' `
  --asset smile.asset.json --max-distance 0.001 `
  --output smile.dense.asset.json
```

独立进程验收以 4 顶点源网格和 9 顶点目标网格运行转移、导入、重开及 BlendShape 构建；目标顶点最大位置误差 `5.96e-8`，控制驱动最大位移 `0.5`。远离源表面的目标被拒绝，不生成资产。命令见 `validation/product_face_transfer_smoke.py`。

身体入口另以自生成 30 关节角色验证：已扰动角色从目标 Pose 恢复后，独立进程读回的完整姿态误差小于 `1e-4`；五帧动画片段捕获、应用与重开后的采样误差为 `0`；同布局重建后可重新采样完整动画；错误兼容摘要拒绝写出，输入场景字节不变。验收命令见 `validation/product_body_entry_smoke.py`。

蒙皮入口使用自生成双关节网格验收：先导出全部顶点权重，修改顶点权重后在另一进程导入，再重新打开场景导出并比较完整文档。已有输出、损坏文档均被拒绝，源场景字节不变。验收命令见 `validation/product_skin_entry_smoke.py`。

FBX 入口使用自生成 30 关节角色验收：从普通场景发布、在新 Maya 进程重导入 31 关节独立骨架并检查三帧 Root Motion 位移；完整采样和无损线性简化都能发布，已有输出和错误帧范围被拒绝，源场景字节不变。验收命令见 `validation/product_fbx_entry_smoke.py`。

动捕入口使用自生成 21 关节 FBX、完整映射预设与已登记 30 关节角色验收。FK、四肢 IK、全身 IK 分别在独立进程导入和写出，三个场景均已重开并捕获角色动画；FK 捕获结果有 14 个随时间变化的控制通道；已占用来源命名空间被拒绝，角色场景和来源 FBX 字节不变。验收命令见 `validation/product_mocap_entry_smoke.py`。
