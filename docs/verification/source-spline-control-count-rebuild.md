# 来源 Spline 控制数量重建

2026-10-01。以原版 6.925 MEL 的 `asFitJointIKInfo`、`asReBuildAdvancedSkeleton` 和 Spline 创建段为依据；原参考文件保持只读。此次补的是现有角色重建流程，不另建求解器或绑定体系。

## 原版行为与接入

MEL 7327–7450 根据 Fit 链中 Mid／数字标签计算控制数量；79355–79361 把两控制器系统补成带隐藏中间控制的三主控图。重建段 77777–78547 重建生成图，再恢复仍存在的控制器连接、形状、Lock/Hide、限制和用户属性；增加控制器后移除不再有消费者的旧末端属性。控制数量变化不保证旧 IK 变形结果逐帧不变，不能把这个入口解释成精确动画重定向。

普通面板重建现在检测当前 Fit 标签产生的数量变化，使用同一个重建入口。保存的 `source_fit_control_count` 记录上一轮实际 Fit 标签数量，兼容旧文件中的缺省值；它与显式指定的生成控制数量分开，使普通同布局重建不会覆盖已保存的布局。底层也支持按系统名传入 `spline_counts`，至少为 2 的整数，拒绝重复、未知系统和其他系统通道变化。该参数不增加新面板布局。

## 生成图和用户数据

- 重新计算目标、位置、Fake Mid、Hybrid、CV、Follow、Twist 和缩放接收图。独立 FKIK 控制器、Body 骨链、绑定长度和矩阵保持原合同。
- 原生动画曲线按仍存在的编号控制器交接；末端 stretch／volume／Follow 等设置按原语义接到新末端。已删除编号的原生曲线解除输出，但保留对象、关键帧和切线，用户数据不被静默删除。
- 生成节点增删记录 UUID 和实际类型；旧节点必须在 AllSet 的明确归属范围内。Maya 自动单位转换按确切生成连接识别。外部用户连接仍须采集，不能用命名空间或名字前缀授权删除。
- Count 变化导致注册成员索引和约束权重别名变化；比较真实成员和驱动关系，注册器独立核对准确成员顺序。其他系统连接和蒙皮数据仍执行原来的严格检查。
- 新 Follow 默认值使用新的编号比例，原作者值／曲线照常保留。现有控制状态和用户选择集交接到对应新节点；消失的编号从集合中移除。
- 带未知用户属性或用户子节点的删除控制器会明确拒绝并回滚，不能当作普通生成节点删除。任意用户附件的重新挂载仍需单独完整迁移。

## Fit 原生驱动保留

此次连续重建发现旧版本首次替换后会丢失原 Fit 与新 Fat 接收器之间的连接。现删除暂存 Fit 之前，记录完整生成图跨 Fit 的输入和输出，按新接收器 UUID 接回保留的原 Fit。兼容旧保存场景时，只恢复六条明确的 Fat 派生连接；目标有用户输入或节点类型／操作不同仍拒绝，不覆盖用户接线。

## 验证范围

Maya 2024 使用上一批保存的原版 biped 绑定场景及局部蒙皮代理网格，已通过显式 2→4→2、原生 Skin／对应动画曲线保留、权重和局部成员保留、增加数量后的单次撤销重做、保存重开，以及之后的普通同布局重建。旧保存场景 Fat 连接恢复后也通过同一连续重建流程。记录为 `validation/results/spline-count-legacy-fit-repair-20261001/spline-count-rebuild.json`。

最终扩展检查全部通过：删除编号的原生曲线保留且解除输出，关键帧值不变；用户选择集保留有效成员并移除消失编号；普通面板入口在显示的 Mid 标签增减后自动完成 2→3→2。完整集中记录为 `validation/results/spline-count-fit-labels-accepted-20261001/spline-count-rebuild.json`，日志为 `validation/results/maya2024-spline-count-fit-labels-accepted-20261001.log`。该运行连续完成五次重建，涵盖显式数量增减、普通同布局以及普通标签增减；增加数量的场景另保存并重开。740 个 Python 源文件静态解析通过；本批数量合同、节点归属、登记、姿态与保留数据的 29 项定向测试通过。

旧 0–1 图若没有保存的 Fit 标签基线，普通重建先保留原布局并建立基线，不依据不完整的旧元数据猜测动画含义。新格式兼容旧缺省字段，既有姿态兼容摘要不受这项作者元数据影响。

上述通过范围针对本机 biped 单个中心 Spline 及所测用户数据，不能扩大到所有侧别／多 Spline 组合、复杂模型变形质量、精确跨数量动画重定向或全部 ADV 功能。旧 0–1 模式图到独立 0–10 控制器的显式升级、完整 Face 及覆盖矩阵中的其余缺口仍须开发与验收。Goal 继续保持活跃，未推送 GitHub。
