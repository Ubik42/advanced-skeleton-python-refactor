# 兼容与旧实现依赖清点

当前运行分层由 `core`、`application`、`adapters` 和 `product` 组成。静态边界检查遍历 `src/adv_py` 中除 `legacy` 目录外的 207 个 Python 模块及 1610 条导入：运行层没有引用 `LegacyMelBridge` 或导入 `adv_py.legacy`；`core`、`application` 与 `product` 没有直接导入 `maya`／`bpy`。Maya 适配层仍有 22 处 MEL 调用，集中在 `maya_body.py` 的 Autodesk FBX 插件参数与导出命令，并非 AdvancedSkeleton 过程调用。

`src/adv_py/legacy/bridge.py` 保留为显式兼容工具；当前产品入口、应用用例和 Maya 运行适配层没有调用它。`adv_migration` 的 MEL 清单命令只读本机授权源码，用于分析，不参与角色构建或动画运行。检查命令：

```powershell
python validation\architecture_boundary_audit.py validation\results\architecture-boundary.json
```

这项检查证明运行代码没有回退到旧 MEL 桥接，不证明原工具的全部行为已被覆盖。仓库不包含授权 MEL 源或逐过程行为映射；当前工作区没有找到可读取的源文件或先前生成的过程清单，因此不能完成原工具逐项覆盖审计。剩余缺口按 [剩余开发清单](剩余开发清单.md) 管理，主要包括不同拓扑的角色重建、广泛生产资产兼容性、自动面部解剖标记、复杂外部动画曲线、交互界面可见会话验收及 Blender 正式迁移。现有同布局重建在自生成 30 关节动画角色及工作台的带面部控制角色上通过。
