# 通用身体模块

身体描述把骨盆到胸部、胸部到头部和左右肩胛的连接顺序作为明确输入。关节名称对应 Body 中的唯一节点，不带 DAG 路径或命名空间；描述中的父子关系必须与实际骨架一致。

```python
from adv_py.adapters import MayaBodyBuildHost
from adv_py.application import (
    CreateFitSkeleton, BuildVariableBodySourceFit,
    BuildOrientedBodySkeleton, BuildBodyCharacterRig,
)
from adv_py.core.variable_body_fit import variable_axial_description

# hero 命名空间需已存在。
host = MayaBodyBuildHost(namespace="hero")
CreateFitSkeleton(host).apply()
BuildVariableBodySourceFit(host).apply(spine_segments=4, scale=1.0, with_hand=True)
BuildOrientedBodySkeleton(host).apply()
rig = BuildBodyCharacterRig(host).apply(
    include_torso=True,
    include_control_spaces=True,
    axial_description=variable_axial_description(4),
)
```

四段脊柱的描述为：

```python
BodyAxialDescription(
    spine=("Root_M", "Spine1_M", "Spine2_M", "Spine3_M", "Chest_M"),
    neck=("Neck_M", "Head_M"),
    scapulae=("Scapula_R", "Scapula_L"),
)
```

`spine_segments` 表示骨盆到胸部的骨段数，含首尾共 `spine_segments + 1` 个关节。生成范围为 1..63 段。合成 Fit 保持胸部端点与四肢位置不变，将原骨盆到胸部的直线均匀分段；它不对既有角色或弯曲脊柱做拓扑迁移。`scale` 缩放整个合成模板，`with_hand` 决定是否生成完整五指。

现有全身构建入口按描述逐节建立 FK 控制器：旋转父控制器时，其后续脊柱、颈头和肩胛控制器继承变换。胸部与骨盆继续提供四肢的连接位置；总控、四肢 FK/IK、五指及标准命名下的头手脚空间可以组合使用。省略身体描述时维持既有标准拓扑。

当前可变链已贯通 Fit、骨架朝向、全身 FK、曲线 IK、伸展、体积保持、头部瞄准和实际蒙皮。标准双段描述继续使用原 RP 求解器；其他段数使用曲线 IK。可变脊柱已接入角色登记和全身动画；曲线脊柱的无跳变模式匹配仍待接入。

`maya_variable_body_smoke.py` 覆盖以下自生成场景：

| 脊柱段数 | 整体比例 | 向上轴 | 五指 | Body 关节数 | 躯干控制器数 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0.5 | Z | 无 | 29 | 6 |
| 4 | 1.0 | Z | 有 | 72 | 9 |
| 8 | 2.0 | Y | 无 | 36 | 13 |

三组场景均验证中性姿态、构建撤销重做、胸部蒙皮网格随脊柱 FK 旋转发生实际变形，以及保存重开后的顶点一致性。验证网格是只受胸部影响的探针，尚不代表复杂生产权重已经验收。

Y 向上场景同时覆盖祖先朝向修改后的子关节世界朝向恢复。朝向计划会包含受祖先修改影响的后代，即使该后代在计划执行前已经与目标世界轴一致；否则父关节转向会使它偏离目标。

## 头部瞄准

全身构建入口增加 `include_head_aim=True`，需要同时启用 `include_torso`。可与标准双段 Spine IK、可变脊柱 FK 或曲线 IK 组合。

```python
rig = BuildBodyCharacterRig(host).apply(
    include_torso=True,
    include_control_spaces=True,
    include_head_aim=True,
    axial_description=variable_axial_description(4),
)
aim = rig.plan.torso.torso.head_aim
print(aim.target)        # 瞄准目标控制器的逻辑路径
print(aim.head_control)  # 头部 FK 控制器的逻辑路径
```

头部 FK 控制器的 `headAim` 属性在通道框中显示为“瞄准权重”。默认值 `0` 保持 FK；`1` 完全跟随目标，中间值混合两种方向。瞄准旋转作用于 FK 控制器的父层，控制器自身旋转继续作为修正，因此瞄准启用后仍可调整头部姿态。

默认视线方向与合成身体的前方约定一致：Z 向上时朝 +Y，Y 向上时朝 +Z。规划时将前方和向上方向转换到头关节的绑定坐标系。头骨指向 `HeadEnd` 的本地轴可能指向头顶，不直接用作视线轴。目标初始位置在头部前方，距离为末段颈头长度的三倍；目标旋转定义瞄准的上方向。整个目标组随角色总控运动。

实现使用原生 aimConstraint、双目标 orientConstraint 和反向权重节点，不依赖表达式、脚本节点或定时回调。FK 参考层与瞄准求解层分离。目标与头部位置重合，或目标方向与上方向平行时无法唯一确定朝向；权重大于零时，角色读取和姿态采样会拒绝该状态。

标准角色登记包含目标平移、目标旋转和瞄准权重共七个通道。完整原位重建根据通道声明重建瞄准模块，保留原生动画和头部蒙皮。可变脊柱也可登记头部瞄准通道，与曲线脊柱参数共同参与全身动画保存和恢复。

`maya_head_aim_smoke.py` 覆盖 2 / 4 / 8 段脊柱、Y/Z 向上、FK 关闭状态不变、目标方向对齐、真实头部网格变形、FK 修正、权重动画和保存重开。标准 30 关节场景另外覆盖带瞄准动画的原位重建、Undo / Redo，以及独立进程中的动画采样和无效目标拒绝。三组场景的保存重开顶点比较误差均为 `0`。


## 可变脊柱曲线 IK

在上述构建调用中启用 `include_spine_ik=True`。非标准双段描述生成独立 FK 链、IK 链和四个曲线控制器，`rig.plan.torso.torso.spline` 返回该模块的计划。四个控制器定义三次曲线，Maya 原生 `ikSplineSolver` 沿曲线求解各段方向；FK / IK 的位置、旋转和缩放混合后驱动 Body。

```python
rig = BuildBodyCharacterRig(host).apply(
    include_torso=True,
    include_spine_ik=True,
    include_head_aim=True,
    include_control_spaces=True,
    axial_description=variable_axial_description(4),
)
spline = rig.plan.torso.torso.spline
print(spline.targets)   # 从骨盆到胸部排列的四个曲线控制器逻辑路径
print(spline.settings)  # 末端控制器，同时承载脊柱参数
```

| 参数或控制器 | 行为 |
| --- | --- |
| `spineIkFk` | 默认 0 使用 FK；1 使用曲线 IK；中间值混合 |
| `stretch` | 默认 1 按当前曲线长度调整每段长度；0 保持绑定长度 |
| `volume` | 默认 1 随伸展缩放关节横向尺寸；0 保持横向尺寸 |
| 第 0 个曲线控制器 | 平移锁定在骨盆，旋转定义起点上方向 |
| 第 1、2 个曲线控制器 | 平移改变弯曲形状，旋转锁定 |
| 第 3 个曲线控制器 | 平移控制胸部端点，旋转定义终点上方向与胸部朝向 |

伸展比使用曲线在机制组局部空间中的弧长除以绑定总长度，因此角色总控等比缩放不会重复计入伸展。实际长度倍率是 `1 + stretch * (弧长 / 绑定总长 - 1)`，限制在 `0.001..1000`。横向尺寸倍率为 `长度倍率 ** (-0.5 * volume)`；伸长至 1.5 倍且体积保持为 1 时，横向尺寸约为 0.8165。该计算提供横截面补偿，不代表复杂网格的最终体积严格守恒。

当前绑定输入要求骨盆到胸部共线、依次向前，骨段沿父关节本地 +X。弯曲绑定链会在场景修改前拒绝；它需要独立的曲线拟合与中性姿态保持设计。四个曲线控制器也不保证能够精确表达任意多段 FK 姿态，当前尚无自动无跳变模式匹配入口。单纯改变 `spineIkFk` 是求解结果混合。

`maya_spline_smoke.py` 已通过 1 / 4 / 8 段自生成场景，包含 Y/Z 向上、五指与头部瞄准组合、中性姿态、Undo / Redo、伸展关闭、总控缩放、实际蒙皮弯曲、参数动画和保存重开。三组重开顶点误差均为 0；四段场景另行注入构建末尾失败，验证节点集合和绑定矩阵整体回滚。篡改绑定长度常量会被图审计拒绝。新增的登记验证覆盖全身动画文档恢复，以及独立 Maya 进程重开后继续编辑；1 / 4 / 8 段身体和蒙皮误差均为 0。


## 角色登记与动画持久化

`RegisterBodyCharacter(host).apply(rig)` 直接接受可变脊柱的完整构建结果。标准双段角色仍写入版本 1；曲线脊柱使用版本 2，增加明确的 `spine_kind: "spline"`，记录全部 FK / IK 机制关节、四个曲线控制器、绑定长度和控制器坐标系。解析器检查字段集合、关节父链、机制链顺序和控制器数量，不通过 Python 对象反序列化恢复计划。

曲线控制通道使用 `spine.spline.0.rotateX`、`spine.spline.1.translateY` 等语义标识；末端三个参数为 `spine.spline.spineIkFk`、`spine.spline.stretch` 和 `spine.spline.volume`。锁定的平移、旋转与缩放不加入动画声明。现有 `CaptureBodyCharacterAnimation`、`ApplyBodyCharacterAnimation` 和动画 JSON 读写入口可直接使用，登记图审计会按实际求解器检查连接。

曲线脊柱暂不接受 `BakeBodyCharacterSpineMode`：四控制点曲线不保证精确表达任意 FK 链姿态，需要专门的匹配与残差处理。


## 可变身体的同布局重建

`RebuildBodyCharacter(host).apply("replacement")` 从原 Fit 和登记的脊柱链重建同一拓扑，颈头链由 `Head_M` 沿父级回溯到胸部恢复。当前保留标准肩胛命名；改变段数、关节连接或绑定位置仍需要专门的迁移计划，不能通过该入口直接替换。

重建继续沿用已有的动画曲线与 Skin 数据交接、旧节点归属审计、原位替换和单次撤销机制。曲线 IK 的求解曲线保留控制点输入连接；只对无输入的控制器曲线复制静态控制点，避免把动画中的求解曲线冻结成某一帧形状。绑定布局在容差内验证一致后，登记保留原始绑定矩阵和长度的精确数值，避免 Fit 往返中的浮点误差使旧动画文件失效。

1 / 4 / 8 段已通过带参数动画和实际 Skin 的原位重建、撤销与重做。身体矩阵最大差异约 `8.9e-16`，蒙皮顶点差异为 `0`；重建后仍可应用重建前保存的动画文档。

四段场景另在旧 Rig 已清理、替换完成后注入故障，验证登记身份和原动画曲线整体恢复。重建场景另存后经独立进程重开，身体与蒙皮采样仍保持上述误差，旧动画文档仍可继续应用。
